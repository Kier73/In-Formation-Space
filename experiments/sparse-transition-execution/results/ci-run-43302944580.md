## Aggregate structural results

Sums across the 48 dense/sparse model pairs:

| Measurement | Dense | Sparse | Change |
|---|---:|---:|---:|
| Parameter slots / stored scalar parameters | 35,024 | 14,897 | 57.5% fewer |
| Weight multiplications | 32,319 | 13,396 | 58.6% fewer |
| Accumulator additions | 32,319 | 13,396 | 58.6% fewer |
| Canonical JSON snapshot bytes | 170,812 | 166,413 | 2.6% fewer |

The sparse stored-parameter sum equals the dense active-parameter sum. The operation counts follow the actual Python forward loops: dense execution multiplies every matrix slot, while sparse execution visits only stored nonzero weights.

The minterm sparse payload is **66.0% larger** as canonical JSON because explicit coordinate indices and pair structure outweigh the omitted zero values at its comparatively high density. Direct-DAG storage improves substantially, and live-DAG JSON bytes decrease by 14.1%. This demonstrates that sparse scalar counts and serialized size are distinct quantities. Canonical JSON size is not resident Python memory; the implementation still uses Python tuples and dense activation vectors.
