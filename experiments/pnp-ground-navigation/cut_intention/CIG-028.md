# CIG-028 — Availability-conditioned continuous computation

Extends CIG-026 temporal images, CIG-027 capacity thresholds, CIG-024 temporal algebra and CIG-025 signed chronological rank. The existing CIG-021 receiver remains the mathematical execution authority. E-CPU SAB-001 (mailcpu/substrate_bootstrap.py) and its integrity-bound checkpoint mechanisms are design references for external host admission and persistence; this experiment does not execute E-CPU leases, authenticated channels or a physical distributed scheduler.

## Piecewise capacity and availability

An admitted finite schedule is a tuple of disjoint half-open intervals (a_j,b_j,H_j,B_j), ordered by time, with an optional infinite final interval. H_j is a declared host label and B_j a logical retained-coordinate capacity in bits. A gap means no available execution host, even if the state needs zero bits. A host offering zero bits is distinct from absence. The schedule is a mathematical caller contract, not inferred from a resource advertisement. Overlapping offers must first be reduced to disjoint selected-host windows by a separate planner.

The image theorem gives b(t) nonincreasing under the fixed qualified law. Let tau_B be the earliest time at which b(t)<=B (infinity if impossible). In each window, the feasible interval is [l_j,b_j) where

    l_j=max(a_j,start,tau_(B_j)).

Discard empty intervals. For an admitted intention with exclusive chronological rank R(t), a finite window contains exactly C_j=R(b_j)-R(l_j) intended events. An infinite final window has infinitely many events if the admitted periodic tail cardinality is positive; otherwise the count is R(D)-R(l_j), with D the transient cutoff and rank constant thereafter. The requested ordinal n is located by subtracting preceding counts, then using the existing CIG-025 select at R(l_j)+remaining. This is exact chronological navigation without iteration over elapsed time or the ordinal. An unrepresentable time/ordinal under the inherited 4096-bit contract is UNKNOWN; it is never admitted as unreachability. Selection is not a proof of all intermediate events having been executed.

Producer thresholds use CIG-027 binary search; the receiver independently scans the finite height breakpoints and checks rank/select with the native CheckedRank. Work is proportional to admitted windows and rank operations, not their durations. The independent threshold scan may be more expensive than binary search; each distinct budget is cached. The admitted schedule allows at most 4096 windows. Source and proof construction costs remain separate.

## Changing offers without changing computational identity

AvailabilityNavigator and AvailabilityAdmission bind schedule content digest, revision, source/decoder/initial anchor identity, root, start and ordinal to every query. revise(windows,effective,expected_revision) replaces future windows only, with effective strictly after the committed coordinate. The exact earlier window partition and host capacities are frozen; historical partition changes and stale revision receipts refuse. Revision numbers advance even if content eventually returns to a previous schedule. The receiver retains its current time, rank and last host when offers change. The operation assumes the caller owns the current schedule and serializes updates; not a distributed lease or concurrent writer protocol.

accept_move first checks the requested destination under the current admitted schedule and then uses the ordinary CIG-026 receiver to check the compact migration against the original CIG-021 anchor. The retained rank advances only on acceptance. The proof distinguishes a mathematically reachable coordinate from an available host window. An unhosted interval means no local materialization at those coordinates; the fixed source law can describe the trajectory across the gap and the next admitted host reconstructs its destination by a logical jump. This is not a claim of real-time activity, resource-free execution, or replay of external side effects.

## Persistence and process recovery

continuation_checkpoint.save flushes a bounded canonical JSON packet and atomically replaces its file using a same-directory temporary file. The packet binds the latest accepted image key, schedule digest, revision, logical time, mixed-radix rank and last host. Its integrity digest is returned. recover creates a fresh producer and requalifies the checkpoint on a fresh independent receiver against the original law/anchor, recomputes the full endpoint code and decoder outputs and checks that the last coordinate belonged to the declared available host. The caller retains a trusted latest digest and admitted schedule revision; digest alone is not authority or rollback prevention. Original source proof, anchor, schedule, and admitted rank language must remain reconstructible independently. The checkpoint is not total memory usage. Atomic replace is local file persistence, not a distributed commit or guaranteed power-loss durability on all filesystems.

A hard process kill test launches an isolated child, advances to t=2 on host-A, writes a checkpoint, and blocks. The parent kills it and launches another process, which recreates the proof/transport, restores the compact coordinate and navigates across the availability gap to t=10 on host-B. The parent separately requalifies the result from the original anchor. A second subprocess control resumes a checkpoint at t=10 and produces t=12. A future-revision test changes the next host from host-B at t=10 to host-D at t=16, preserving the accepted t=2 coordinate; the old query is refused.

## Executed independent mathematical control

A separate seeded JavaScript oracle ran 160 nonlinear block-transport laws, 1,920 changing-window ordinal queries, comparing interval rank arithmetic against explicit finite image evolution and per-time trajectory checks. All matched: 893 FOUND, 1,027 UNREACHABLE, 80 laws with nonstationary trajectories, 100 zero-bit hosted destinations, and 333 found queries that started in a schedule gap. These are executed mathematical controls, not the new native package test results.

## Native campaign

test_availability_time.py checks full-domain images, explicit periodic trajectories, finite and infinite windows, zero-bit hosts, no hosts, forged receipts, revision controls and subprocess recovery. run_availability_time.py reuses CIG-027's ordinary source CNF fixture with irreversible and continuing nonlinear lanes; the rare intended event occurs at multiples of its analytic period P. The schedule admits t=0 on A, P on B, 3P on C, then multiples starting at a 1001-digit time. It checks exact ordinal selection including a 901-digit ordinal. After committing P, replace C's future window with host-replacement at 4P, reject the old receipt, persist and restore the admitted coordinate, then navigate across the gap with the native NCR-008 codec. Compare migrated observation codes to the binary-composition oracle and the original decoder expressions. The benchmark measures source, image/time admission, rank compilation/check, schedule construction/check, revision, file checkpoint, restoration, query and migration separately.

```sh
python -m unittest test_availability_time -v
python run_availability_time.py --sizes 24 96 1023
# Pinned NCR checkout on PYTHONPATH:
python run_availability_time.py --native-ncr --sizes 24 96 1023
```

## Next development

Use E-CPU's admitted resource advertisements and receiver-local authorized implementations (SAB-001), durable quorum fencing and process recovery as the source of schedule evidence, not host strings. Add measured working-set/transfer costs rather than ideal retained bits; distinguish a cheap endpoint from a feasible migration requiring temporary memory. In particular, a compressed state can never silently reconstruct distinctions discarded by the earlier observer contract. Schedule and computation identity should remain separate, with explicit source/intent epoch migration.
