# CIG-029 — GitHub-native bootstrap of a continuous nonlinear processor

Connects the actual CIG-021 source-qualified transport/decoder, CIG-024/025 time-set and rank algebra, CIG-026 native NCR-008 codec, CIG-027 capacity thresholds and CIG-028 availability/recovery to E-CPU SAB-001.

The existing [E-CPU Virtual Processor workflow](https://github.com/Kier73/E-CPU-Virtual-Processor/blob/e3a511369756929b518df11f5f7c0ff161d143ce/.github/workflows/processor.yml) demonstrates a durable Git-branch cursor and serialized publication across workflow dispatches. In-Formation-Space's independent-host operation path and proof-runner three-host workflows demonstrate GitHub artifact transfer between jobs. This increment uses the latter transport to avoid writing a new persistent state branch before verification. The real native SAB operation is local to each runner; GitHub Actions actually transfers the continuation artifact. No in-memory identity carrier is passed off as a remote connection.

## Contract

Each of three source-qualified nonlinear workloads has 24, 96 or 1,023 observation bits, with reversible nonlinear spatial marker cycles alongside irreversible local maps. The source is the ordinary shuffled CNF generated by CIG-027, and the original CIG compiler derives the executable decoder, independently qualified transport and source section. The rare goal occurs exactly at multiples of the marker period P. The time-set algebra also derives an always-true intention through a verified Boolean expression.

The three hosted stages intentionally have disjoint logical availability windows:

1. Linux seed runner: t=1, capacity k-d where d is the number of contracting lanes. Admit and persist the coordinate.
2. Windows contract runner: recover the original coordinate on a fresh source-qualified receiver, navigate to t=3 under capacity 3l, where l is the number of persistent lanes. Then replace the future window at P by an open window starting at S=10^1000+173. The previous availability receipt is refused under revision 1.
3. Linux resume runner: independently replay prior publications, recover the compact coordinate from the checkpoint, then navigate to the (10^900+173)-rd rare intended event from S. The analytically expected destination is P*(ceil(S/P)+10^900+172).
4. Separate Windows audit: independently recompile the original source, verify every native SAB task/plan/receipt, exact temporal selection, representation migration, revision and checkpoint, and compare the final code against the independent binary composition oracle. The remaining process continues to evolve (T(u) != u).

Each stage checks the independent fixture decoder outputs and exact bits. The mathematical state identity does not contain the host. The schedule is caller-declared logical availability, not a forecast of real GitHub runner wall-clock availability.

## Native E-CPU admission

The workflow checks out the exact source revisions E-CPU df75e8dee43c48c93bdca73637dada95c7d53f81 and Navigable-Compute c249a482a0a09e24b3a2af5b39d43a45856e2bc6 and installs them with no fallback. Each job constructs a typed ResourceObservation with a single offered operation cig-migrate and actual observed job/OS/runtime metadata. The local installed handler and independent CIG receiver oracle are bound in RealizerBinding, admitted by a narrow BootstrapPolicy. AdaptiveBootstrap.plan/execute form and execute the intention-to-qualified-coordinate task. The receiver checks the proposed migration in a detached image before committing the actual cursor. A negative control removes the locally bound handler and requires planning to refuse the same sensed offer. The audit reconstructs the native task and plan and calls verify_bootstrap_report; it separately verifies the mathematical semantics instead of treating that report hash as proof.

Artifact publication is via actions/upload-artifact and actions/download-artifact. A SHA-256 of the exact serialized bundle is transferred separately through the predecessor job output. The bundle retains earlier records, parent digest, SAB report, original/revoked schedule receipt and last checkpoint. A subsequent job checks the artifact digest and all prior records, then creates a separate fresh receiver and restores the last accepted coordinate with continuation_checkpoint.recover. It does not copy the old process or RAM. A fourth job replays the full history and binds the reported job identities to the current workflow run, attempt and commit, requiring Linux/Windows/Linux. The operating-system diversity is workflow evidence, not hardware identity or physical attestation. No tokens, private network addresses or whole environment snapshots are recorded.

GitHub's job outputs and artifact access are the trusted channel in this experiment. Unkeyed digests alone cannot authenticate a malicious runner, and the audit does not establish a globally fenced distributed journal. Rerun the whole chain for a new workflow attempt. Read-only repository permissions suffice for the experimental chain. No external arbitrary-code service, new public listener, or long-lived secret is provisioned.

## Reproduction and tests

```sh
# Install the two pinned repository packages first.
python -m unittest test_github_continuation -v
python github_continuation.py seed --output a.json
python github_continuation.py contract --input a.json --expected <digest-from-seed> --output b.json
python github_continuation.py resume --input b.json --expected <digest-from-contract> --output c.json
python github_continuation.py audit --input c.json --expected <digest-from-resume>
```

The workflow executes these stages on actual separate runner jobs and retains the audit artifact. Unit tests cover a full local 24-bit chain, missing binding refusal, wrong artifact digest, wrong predecessor, altered checkpoint, rehashed forged migration, and future-schedule expiry. The native campaign and runner transfer are separately verified by CI; no success is assumed before exact-head results.
