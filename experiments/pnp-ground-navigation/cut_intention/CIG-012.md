# CIG-012 — Memory-aware navigation of source-equivalent architectures

Research continuation of CIG-008 (composed mathematical Grounds), CIG-009 (regional structural memory), CIG-010 (adaptive structural continuity), and CIG-011 (costed architecture navigation).

## Question

Can an independently verified conditional-count interface be reused when the architecture that realizes it changes? Can the choice of architecture depend on the receiver's retained evidence rather than on cold construction costs alone?

## Exact mathematical construction

For a finite Boolean region, let V be its complete variable domain, C its owned canonical CNF clauses, and B a subset of V exposed to the surrounding computation. The conditional-count interface is

`M_(V,C,B)(b) = sum_{h in {0,1}^{V\B}} [C(b,h)]`.

Two distinct derivations with the same V, C, B compute the same function. V includes unconstrained variables: omitting even an unconstrained variable can change the multiplicity. Clause coverage alone is insufficient. This is a regional semantic identity independent of the architecture's proof tree, not a canonical identifier for every logically equivalent CNF.

If B' is contained in B, the exact translation is

`M_(V,C,B')(b') = sum_{b: b|B'=b'} M_(V,C,B)(b)`.

It follows by partitioning the same set of satisfying assignments. No inverse is available in general: distinct conditional distributions can have the same sum. An old coarse count cannot certify the newly exposed conditional counts. When the destination exposes a coordinate that was eliminated, the archive must find another independently admitted finer interface or compute a fresh function.

For joins with child domains V1,V2 and child boundary sets B1,B2, the independent coverage checker requires disjoint clause ownership and that every shared variable and every requested output variable in a child domain be exposed by that child. This prevents double-counting a hidden shared coordinate. The ordinary CIG-010 source audit checks complete source ownership and destination boundaries before realization.

## Implementation

- `architecture_memory.py`: `Archive.obtain` is a drop-in receiver-local memory for the actual `adaptive_ground.realize` traversal. It derives internal source coverage from admitted child messages. It records exact structural coverage tuples (not merely hashes). Direct proof reuse precedes source-region transfer; then checked marginalization; otherwise ordinary CIG-009 producer and independent `verify_message`.
- `verify_architecture_memory.py`: separate checks for scope/clauses, shared-coordinate retention, equal interfaces and independently replayed projection. A rekeyed transferred message remains bound to the destination descriptor, rather than masquerading as the original proof identity.
- `Archive.estimate`: metadata-only preview using admitted coverage and interface variants. Candidate source audits are charged to selection time; no candidate count realization or archive mutation is required. The estimate may overstate new work if a candidate can itself create additional reusable messages. It does not predict full wall-clock time.
- `choose`: minimizes `fresh_producer_cells + projection_cells + check_weight * new_full_checks + message_weight * destination_nodes` over the finite supplied, qualified catalog. Weights are declared cell-equivalent prices, not measured communication latencies. Destination node costs include all nodes, even admitted hits. Candidate construction is external to the timed selector.
- `coarsen`: collapses a subtree to an explicitly scoped leaf when its scope fits the width budget. This preserves exact ownership and boundaries at the collapsed region. It differs from independently repacking source clauses into an unrelated partition.

The realization uses the existing CIG-008 normalization and affine/Boolean machinery; CIG-009 producers and source replay; CIG-010 annotated trees and complete witness construction; CIG-011 graph packing and independent cyclic transfer-matrix oracle. This experiment does not start a new authority system. Receiver memory is process-local. External publication, crash recovery, and authenticated remote admission would need existing E-CPU mechanisms.

### Directional controls at 8,192 variables

- Independently packed width-8 architecture: only 6 of 2,731 destination messages transfer, 2,725 new full checks, 294,808 new producer cells. Warm 1,492.40 ms versus cold 1,487.44 ms. Arbitrary repartitioning is still a genuine open translation problem.
- Coarse-only archive to fine architecture: 4,095 transfers and 4,096 fresh checks, 24,576 new producer cells. The previously eliminated finer region information is not fabricated.
- Fine -> aligned coarse -> fine: all 8,191 original proof identities recover; no new full checks.

### Architecture selection with memory

At zero message/check price and empty archive, the selector chooses fine (57,332 producer cells) instead of aligned coarse (81,908) or independently packed coarse (294,896). With only aligned coarse admitted and the identical zero-price objective, it chooses aligned coarse (0 fresh cells) instead of fine (24,576). With fine admitted and a message price of one, the aligned coarse costs 4,095 units compared with fine at 8,191, so the same mathematical source is realized by a smaller architecture using retained interfaces. This is a finite-catalog optimization, not an optimal architecture proof.

Selection overhead is substantial: at 8,192 variables, the cold catalog preview took 1,212.71 ms and the fine-resident preview 1,584.72 ms, before realization. The measured warm realization advantage is not an end-to-end win if that entire selection pass must be charged to one operation. Candidate layout generation is also outside these timing columns.

### Revision campaign

Sixteen reproducible source revisions at 256 variables, including four UNSAT contradictions. Every selected result matches a fresh Archive realization, the alternate qualified architecture, and the independent transfer-matrix oracle. Both starting layouts are pre-admitted; each alternate is also realized after the measured selected realization for validation and enriches the archive, so this is not a single-policy deployment comparison. All sixteen selections choose coarse at check weight 4 and message weight 1. New full checks: 112 (at most seven per revision), against 2,032 cold checks. Producer cells: 1,216 versus 40,768. Warm realization totals 152.29 ms versus fresh 373.78 ms, excluding selection and the extra validation realizations. Selection adds 306.84 ms, bringing measured selected warm plus selection to 459.13 ms, slower than fresh realization alone. This makes incremental catalog scoring a concrete performance target.

## Next research direction

Two ways to reduce the remaining overhead are complementary:

1. Incrementally maintain verified coverage identities and candidate costs, so a local architectural/source change does not require hashing and auditing the entire catalog. The existing archive deliberately stores complete source coverage; sparse exact set commitments and checked local changes are a possible refinement.
2. Introduce common-refinement translations. If a destination region is an exact union of previously admitted subregions with disjoint clause ownership and sufficient exposed coordinates, combine their functions and marginalize. Where a previous region hid a now-required variable, retain a richer interface deliberately, or generate fresh evidence. Choosing which coordinates to preserve is an intention-dependent investment in future navigation, with memory, communication and verification costs explicitly charged.

This yields a directed space of mathematical architecture transformations: source-equivalent reorganization, exact forgetful projection, and evidence-requiring refinement. The important distinction is that describing an architecture makes it a navigable object; an efficient and verified route to an intended architecture remains a computational construction problem.
