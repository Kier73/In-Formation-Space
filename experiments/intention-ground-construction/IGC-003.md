# IGC-003 — Intention-constructed Ground over authenticated E-CPU execution and quorum recovery

**Scope:** real native E-CPU Hypervisor operations over mTLS sockets, independent compute receiver processes, and real three-member E-CPU recovery lineage, all on the same GitHub Actions runner. This does not prove geographically separated hosts, Byzantine resistance, arbitrary natural-language/VM synthesis, or permission to execute from a mathematical receipt.

## Composition: no competing runtime

Existing work: [IGC-001](README.md) synthesizes a minimal DFA from a regular-language intention and independently checks all-word equivalence plus minimal-state witnesses. [IGC-002](IGC-002.md) executes that constructed machine in successive receiver-owned E-CPU Virtual Layers with file handoff. This experiment adds **two existing E-CPU capabilities**, rather than creating any new transport or consensus logic:

- `mailcpu.mtls_transport.connect_mutual_tls/accept_mutual_tls`, `SocketTransport`, `ReliableChannel`, `HypervisorOperationChannel`, `HypervisorOperationResultChannel`, and `VirtualLayerRuntime.receive_and_execute` carry a real native operation through bidirectionally authenticated TLS. An actual receiver-owned HeadlessOS and Hypervisor arbitrate and perform the fixed pure DFA transition.
- `DistributedRecoveryLineageCoordinator`, `RecoveryLineageAuthority`, `RecoveryLineagePeerClient`, `RecoveryStateManifest`, and the unchanged E-CPU remote authority service own recovery high-water. The configured A/B/C fixed membership has strict majority quorum and independent durable journals.

The same source-pinned, independently reconstructed three-state Ground `(0|1)*01` drives both stages.

## Evidence path

1. The source is provided as a declared typed intention and IGC-001 constructed receipt. The **receiver** independently invokes Node's different Thompson-NFA verifier, checks all-word equivalence, pairwise distinctions, host state capacity, and a **receiver-provisioned** intention SHA. A hash is not a signature.
2. B is a separately launched mTLS receiver process, with its own admitted system Ground, fixed operator specification, local compute capability and Hypervisor. A has a distinct owner/client certificate. Only a native `VirtualLayerWorkload` / Hypervisor event containing the next token is transmitted; no sender code or power to grant rights.
3. B computes `0` and returns a **native** `virtual_layer.operator_result` over the E-CPU result channel with reliable request/result acknowledgement. The source mathematical Ground determines the expected next state `1`; the client checks the exact receipt and immutable predecessor.
4. Owner A uses two remote, independent mTLS `RecoveryLineageAuthorityService` processes (B and C, **separate from the compute services**) to seal generation 1 and store a content-addressed full checkpoint. The completed coordinator exits and a new owner connects, learns high-water from the authority quorum, chooses the exact archived bytes and mathematically re-verifies the full history.
5. A new mTLS compute receiver C, with separate process, certificate and admitted Hypervisor, executes token `1` from the recovered state. The intended state becomes `2`, accepting. The new owner seals generation 2 and another fresh owner discovers only the current quorum root.
6. A candidate for the valid but older generation is refused. Removing quorum services, altering sealed checkpoint bytes, substituting TLS hostname or lacking receiver compute capability must also refuse.

### Authority and physical scope

The test creates ephemeral CA-signed owner/member identities via **E-CPU's existing test fixture**, uses TLS 1.2+ with server hostname and client certificate verification, and interacts with genuine OS processes on loopback TCP. The authority B/C services and separate B/C compute receiver processes reuse their test identities and certificate files. This is a controlled single-runner authentication experiment, **not independently managed private keys on separate physical machines**.

The low-level E-CPU quorum has fixed-membership, durable majority semantics. Its returned roots and manifests select the checkpoint state: a valid historical checkpoint cannot supersede the highest quorum-supported generation. An attacker controlling the trusted owner journal or member quorum is **not** addressed. The external archive must actually retain exact bytes. The receiver has no general ability to reconstruct missing archived checkpoint data from mathematical identity alone.

The recovery process never receives a proposed candidate checkpoint, only a provisioned mathematical source and an addressable external archive. But its external source files and A's TLS keys remain provisioned by the test harness: there is no external public-key signature over the IGC-001 intention itself, nor a bootstrap for arbitrary anonymous network participants.

Each new receiver separately requires its *own* Hypervisor compute capability. Quorum historical state and source mathematical possibility grant no execution rights.

### Reproduction

The dedicated workflow [IGC-003 authenticated Ground over mTLS quorum](../../.github/workflows/igc003-authenticated-quorum.yml) pins exact E-CPU revision `42aa58c289f62329deb14ced9b5d09f104b92837`, provisions OpenSSL and Node 22, then runs on Python 3.11/3.13:

```sh
python -m pip install -e external/E-CPU
python -m pip install pytest
python -m unittest discover -s experiments/intention-ground-construction -p 'test_construct.py' -v
python -m unittest discover -s experiments/intention-ground-construction -p 'test_authenticated_quorum.py' -v
```

The retained nonsecret evidence bundle contains the accepted canonical checkpoint and a four-component provenance summary. It does not include a private key or assert network-independent machines.

### Next experiments

Use two independently managed CI runners or remote hosts rather than multiple processes on the same GitHub runner; provision distinct credentials with clear rotation/revocation. Introduce owner hard-kill during an *unacknowledged* semantic operation and prove that the native response and quorum state reconcile without duplicate committed effects. Test dynamic rehome through the E-CPU ComputationalFabric directory with native lease and requalification, and measure end-to-end bytes and costs against a direct finite-state interpreter.

The important research result to test is not that a regular-expression recognizer exists. It is whether **an intended behavior can construct its own verified state-space, whose very same mathematical identity survives authenticated execution, independent recovery, movement to a distinct host, and renewed local authorization**.
