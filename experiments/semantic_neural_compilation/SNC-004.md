# SNC-004 — Federated semantic-model admission across isolated hosts

**Experiment:** SNC-004A: independently verified portable mathematical model
capsules crossing distinct GitHub Actions runner jobs, with a third
reconstruction host. This is an **artifact-mediated federation test**, not
a live inter-host mTLS or Tailscale session.

## Question

Can a new host reuse a neural realization supplied by a different host
**without** trusting that source host's authority, reconstructing its
weights from scratch, or losing the complete all-real mathematical proof?

SNC-001 created architectures from exact mathematical descriptions.
SNC-002 moved descriptions over E-CPU authenticated transport.
SNC-003 stored source-addressed verified architectures across restarts.
SNC-004 adds receiver-owned independent admission of an already
materialized, portable neural certificate and a separately reconstructed
third-host observation.

## Actual trust separation

- The **producer** owns a local SQLite database and source policy. It can
  export a canonical SNC-001 certificate for its own source_clamp name.
  The exported file contains only a schema, exact semantic digest, full
  generated-network digest and a portable certificate. The sender's
  policy and SQLite database never accompany it.
- The **receiver** owns a different policy and local SQLite database.
  It chooses a different alias, clamp, and pins the expected exact
  semantic digest independently from the checked-in test description.
  The sender's alias or claimed trust is not meaningful to the
  recipient. The recipient independently runs SNC-001/COE-002
  complete-domain certificate verification; only a successful result
  allows insertion into the receiver's local mathematical cache.
  It rejects a corrupt or conflicting existing realization rather
  than silently overwriting it.
- A fresh receiver host object restores the imported model and
  independently checks it again before evaluating x=3/4, producing
  the exact rational answer 3/4 without rerunning neural construction.
- A third auditor job uses an independent certificate checker and
  its own exact rational network interpreter to verify the original
  all-real semantic function, recompute the requested observation,
  check the model identity and exact receipt digest, and reject a
  forged response even if its digest was recomputed.

The protocol carries no proof of external source authenticity or
delegated execution authority. SHA-256 consistency and a mathematical
certificate are not a cryptographic issuer signature. The receiver
permits only those mathematical descriptions listed in its own
read-only policy context. No VGI Ground is thereby admitted, and
external side effects are never authorized.

## Reproducible GitHub experiment

The workflow .github/workflows/snc004-federated-hosts.yml has:

1. Local contract tests under Python 3.11 and 3.13, including
   adversarial source substitution, certificate tampering, noncanonical
   JSON, conflicting existing cache entries, revocation, concurrency,
   and independent audit of forged outputs.
2. **Producer-host:** a GitHub-hosted runner creates and independently
   verifies a model, then uploads *only* the untrusted portable model
   artifact. Its database and source policy stay on its runner.
3. **Receiver-host:** a separate GitHub-hosted runner downloads the
   portable model and independently admits it under its own semantic
   policy and distinct model alias. It retains an exact observation
   report, not the sender's policy or authority.
4. **Auditor-host:** a third runner downloads the untrusted export and
   receiver report, independently checks complete-domain equivalence
   and evaluates the reported observation using a separate rational
   interpreter. It publishes its own report.

The jobs run in distinct hosted execution environments, but we do not
assert separate physical computers or an active network socket
between them. GitHub Actions artifacts are explicitly used as the
transfer medium; the certificate is treated as untrusted content.
These jobs are not a substitute for authenticated public or overlay
network transport.

The sender's and receiver's source-policy inputs originate from the
same checked-in example in the source repository. That is an
experimentally controlled comparison, not independent administrative
governance or live certificate-based identity federation.

## Invariants tested

- **Source authority:** Import rejects a model that is not present in
  the recipient's own allowlist, even if the source host admitted it.
- **Mathematical independence:** The importer never invokes the neural
  compiler; it independently rechecks the transferred coefficients,
  hidden ReLU activation cells, full-domain equality, and digest
  identities through COE-002.
- **Deterministic custody:** Existing cached models under the same
  (local alias, semantic digest, compiler version) key must be
  byte- and identity-identical. Corrupt or conflicting entries fail
  closed, including after digest recomputation.
- **Durable reuse:** Source-free input observations can use a verified
  restored realization. Incoming source metadata does not write
  recipient policy or grant external computation rights.
- **Independent reconstruction:** The auditor interprets the
  transferred neural parameters without loading the original
  semantic-to-neural compiler and compares the exact rational output
  to the receiving host receipt.

## Run locally

Use Python 3.11+ and the standard library. Add both directories to
PYTHONPATH:

- experiments/semantic_neural_compilation
- experiments/continuous-observation-equivalence

Run the SNC-004 test file with unittest discover using pattern
snc004_tests.py.

To reproduce the artifact protocol manually, run the following in
separate scratch directories:

1. Invoke federated_pipeline.py producer with --directory
   /tmp/snc004-source
2. Copy only /tmp/snc004-source/portable-model.json to a fresh
   recipient folder. Do not copy policy, database or certificates.
3. Invoke federated_pipeline.py receiver with --directory
   /tmp/snc004-dest and --capsule
   /tmp/snc004-source/portable-model.json
4. Invoke federated_auditor.py with --capsule pointing to the exported
   model, --receiver-report pointing to
   /tmp/snc004-dest/receiver-report.json, --examples pointing to
   experiments/semantic_neural_compilation/examples.json, and
   --output /tmp/snc004-third-audit.json.

## Next frontier: SNC-004B active inter-host transport

To establish a *live* independent-machine claim, the same portable
capsule and receiving policy must pass over E-CPU ReliableChannel
and mutual TLS through a reachable Tailscale overlay endpoint,
not a GitHub artifact. The repository has an IHP-006 design using
GitHub workload identity federation and a dedicated ephemeral
tailnet. Its previously documented preflight had missing federation
credentials: do not infer a successful overlay merely from CI
success or public artifact transfer.

A dedicated credential-scoped SNC-004B run should arrange independent
sender/receiver certificate generation, per-run peer public-key
attestation, bounded E-CPU mTLS transfer, a reverse application
receipt (transport ACK is insufficient), and third-host
reconstruction of the resulting exact network and observation. No
sender policy or private credential should travel through the
bootstrap mechanism. Keep overlay reachability, admission, proof,
and external execution as separate observations.

The verified mathematical language remains 1D rational continuous
piecewise affine maps and ideal affine/ReLU arithmetic, not general
GPU inference or model learning.
