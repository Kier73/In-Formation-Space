# SNC-003 — Persistent semantic hosting and verified observation reuse

**Status:** Experimental successor to merged SNC-001 and SNC-002.

## Question

Can the receiving E-CPU observer construct a mathematical neural realization once,
retain and reuse it as a durable semantic resource, and enforce an independent
receiver-owned source identity after process restarts?

SNC-003 uses one scalar real input, rational affine/ReLU models, exact
fraction observations, and SNC-001's independent COE-002 certificate
checker. No transformer training, GPU execution, whole-model serving, or
external effect authorization is demonstrated.

## Architecture

The persistent_host.py module provides a bounded SQLite-backed semantic host.

- Receiver-local canonical policy maps named model IDs to exact semantic
  atlas SHA-256 digests. Client messages cannot grant or change authority.
- A first seed transfers the mathematical atlas, without weights.
  The receiver compiles a rational ReLU realization, produces an
  activation-cell certificate, independently verifies complete all-real
  semantic equivalence, and commits the capsule under a content-derived
  semantic address and pinned compiler version.
- Later observe requests carry only a model ID, coordinate and request
  ID. They send no weights, atlas or proof.
- Same-process requests reuse the verified model without recompilation or
  independent full certificate verification for each observation.
- New processes independently verify the saved capsule, model digest,
  and receiver-owned source pin before hydrating the model from SQLite.
  They do not rerun the neural compiler.
- BEGIN IMMEDIATE transactions serialize model insertion and exact
  observation receipt writes. Retries with identical IDs and inputs
  return the prior exact result; conflicting IDs or damaged receipts
  fail closed.

The receiver rereads policy on every request. Model removal denies even
an in-memory realization. Rebinding a model to a different allowed digest
does not allow its old realization to be read. Observation receipts
are *not signed attestations* or capability tokens.

## Real E-CPU transport

The persistent_wire.py module uses MailCPU SocketTransport and
ReliableChannel over mutual TLS with explicit DNS peer identities,
following SNC-002's existing implementation at E-CPU revision
3b57adcc2baaaa7e56e4bab943946f4e87e95c65.

Separate reliable request and response channels mean a delivery ACK
never stands in for a mathematical or authority decision. The receiver
returns an explicit application response: accepted exact observation,
or rejected request. A complete request is bounded in size and has
an exact schema. Arbitrary wire-supplied policy fields are rejected.

## Live experiment

The run_persistent_host.py runner creates ephemeral local test-only
CA and leaf certificates, and starts separate sender and receiver
processes over loopback TCP. A new receiving process is started for
each independent session:

1. Cold seed transmits the clamp 0..1 mathematical atlas and verifies,
   constructs, and durably commits its neural realization.
2. A fresh receiving process accepts only a short reference and new
   coordinate, re-verifies the stored capsule and executes exact
   rational observation without reconstructing weights.
3. Another fresh receiving process accepts the same request ID as
   the previous observation and must retain the same durable receipt.
4. Another host object restores the capsule and performs 32 distinct
   same-process warm observations with no additional model construction
   or full certificate replay.

The retained report separates application request bytes, separate
process wall-clock, local first-use construction/verification costs,
and in-process reuse timings. It does not combine unrelated clocks.

## Run

With Python 3.11+, OpenSSL CLI, and pinned E-CPU checked out at
external/E-CPU, set PYTHONPATH to the colon-separated entries:

- experiments/semantic_neural_compilation
- experiments/continuous-observation-equivalence
- external/E-CPU

Run the SNC-003 test file with unittest discover, pattern snc003_tests.py,
then run experiments/semantic_neural_compilation/run_persistent_host.py
with --output snc003-host-report.json.

GitHub workflow: .github/workflows/snc003-persistent-host.yml

## Evidence and limitations

Adversarial tests reject altered or rehashed weights that change the
function, corrupt serialized cache bytes, changed source identities,
policy revocation, policy rebinding, conflicting request IDs,
modified durable observation receipts, malformed clients, and
concurrent duplicate construction. Receiver-owned policy is separate
from all requests.

Durability is local to one SQLite trust context. A compromised
administrator with policy and filesystem access may roll back or
replace files; SQL hashes are not externally authenticated signatures.
The test uses different Python processes but **one physical runner**.
It is not a cross-host federation, public internet or Tailscale test.
The generated model retains ideal exact mathematical semantics,
not a guarantee of floating-point hardware accuracy. There is no
VGI Ground admission or external E-CPU effect authority.

## Next discriminating experiment

distribution, E-CPU operational admission, explicit active model

restoration, repeated inference, and authenticated network overhead

cache hits as an implicit authorization.
