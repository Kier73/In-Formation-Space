## Important interpretation

The 292-to-132 byte reduction concerns only **application request
bytes** and specifically compares a cold *source seed* against a
reference-only *warm request*, not whole TLS traffic or equivalent
transfer initial conditions. The first process session took about
**1.171 seconds** end to end and the restart reference session about
**1.186 seconds**: it is not legitimate to claim an end-to-end
latency speedup from the smaller reference message. Process startup,
certificate fixture, transport and shutdown dominate this measurement.

All persisted models are re-verified under a receiver-owned pin when
a new process first reads them, rather than blindly trusting local
SQLite bytes. Same-process reuse skips redundant construction and
certificate replay, but still checks the live receiver policy on each
request. Damaged cache bytes, swapped/rehashed weights, changed
source policy, forged observations and conflicting request IDs are
required to fail closed by the adversarial tests.

No independent physical hosts, external issuer identity, signed
anti-rollback ledger, floating-point/GPU numerical guarantees,
VGI Ground authority or externally side-effecting E-CPU VM operation
are claimed.
