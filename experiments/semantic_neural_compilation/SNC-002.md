# SNC-002 — Source semantics in transit; neural architecture at the receiver

**Status:** Experimental companion to merged [SNC-001](https://github.com/Kier73/In-Formation-Space/pull/176).
**Scope:** exact scalar-real rational piecewise-affine descriptions, locally separated
Python processes, real E-CPU \`SocketTransport\` + \`ReliableChannel\` over mutual TLS.

## Question

Can a sender transmit only a finite, pinned **mathematical description** of
a neural function and let the receiving machine construct, verify and
realize a new neural network *at its destination*?

This is distinct from PNF-002, which transports already materialized neural
parameter tensors. The semantic path here transmits **no neural coefficients,
network architecture, or preconstructed COE certificate**. The recipient
runs SNC-001's constructive compiler itself.

## Source-only protocol

The wire document has exactly three keys:

\`\`\`json
{
  "schema": "in-formation-space.snc002.semantic-transfer/0.1",
  "kind": "semantic",
  "semantic_atlas": [
    {"left":"-inf","right":"0","affines":[["0","0"]]},
    {"left":"0","right":"1","affines":[["1","0"]]},
    {"left":"1","right":"+inf","affines":[["0","1"]]}
  ]
}
\`\`\`

The receiver is provisioned with an independently chosen expected
semantic SHA-256 hash. It must **not** derive that authority from the
transmitted document or its transport manifest. After reconstructing the
source description, it:

1. Validates the source exact intervals, continuity, rational tokens and
   resource ceilings.
2. Constructs a fresh two-layer ReLU realization from slope differences
   using the existing SNC-001 compiler, including a new portable COE
   activation-cell certificate.
3. Invokes the **separate** SNC-001 receiver verifier, which in turn
   invokes the COE-002 independent certificate checker, to establish exact
   all-real semantics.
4. Checks the receiver-owned semantic pin against the verified atlas.
   Only then reports a verified mathematical realization; no E-CPU
   execution or Ground authority is thereby granted.

The **parameter baseline** instead sends a canonical JSON document whose
\`generated_certificate\` contains the explicit neural weight matrices,
biases, activation labels, source semantics and complete COE-002
activation cells. The receiver does **not** call the neural compiler in this
mode; it independently verifies the transferred certificate against the
same receiver-owned semantic pin. This is a comparison with
*verified parameter transport*, **not** raw weight bytes or a compact
binary tensor format. Both paths must produce identical generated-network
SHA-256 and complete-domain semantics to be compared.

## Real E-CPU communication

\`semantic_transit.py\` uses the existing pinned E-CPU implementation,
commit \`3b57adcc2baaaa7e56e4bab943946f4e87e95c65\`:

- \`connect_mutual_tls\`/\`accept_mutual_tls\` check CA trust and expected
  peer DNS SANs \`snc002-origin\` and \`snc002-recipient\`.
- \`SocketTransport\` conveys actual E-CPU framed message objects.
- \`ReliableChannel\` sequences and acknowledges each bounded document
  manifest, ordered 8,192-byte hex chunks and terminal manifest digest.
- A strict decoder checks the exact version, channel, mode, body size,
  canonical bytes, chunk order, counts, per-chunk length and SHA-256
  before parsing or constructing a network.
- A transport ACK is a delivery observation only. Even a correctly
  delivered but rehashed altered model must be rejected by the
  receiver-side semantic verification.

The live demonstration starts a fresh receiver **Python process** listening
on loopback TCP, then starts a different sender **Python process**. It
generates a short-lived ephemeral CA, server leaf and client leaf for
the test. No service or persistent PKI is provisioned.

## Comparison and measurement

The same process-pair procedure is run in both transfer modes for
\`clamp_0_1\`, \`triangular_bump\`, \`vector_x_abs\` and
\`zigzag_32\` (33 canonical regions, 34 hidden neurons).

The resulting JSON report retains:

- **Actual application payload bytes** (not estimated serialized size).
- Reliable frame count acknowledged by the sending process and received
  by the independent process.
- Local sender ACK-completion duration.
- Local receiver transport, construction and independent verification
  durations, measured with monotonic nanoseconds.
- A **same-host parent process** end-to-end elapsed duration, including
  process setup and receiving verification.
- Matched exact semantic and generated coefficient identities, TLS
  negotiated protocol and peer certificate digest.

It does not combine sender-local and receiver-local timestamps as if
independent hosts had a synchronized clock. It does not claim network
packet-byte counts, public-internet performance or that symbolic transfer
must be cheaper. A JSON certificate can be much larger than bare weights;
its proof material is part of this explicit comparison.

## Reproduce

From the In-Formation-Space root with the pinned E-CPU repository
checked out under \`external/E-CPU\`, Python 3.11+, OpenSSL CLI:

\`\`\`bash
export PYTHONPATH=experiments/semantic_neural_compilation:experiments/continuous-observation-equivalence:external/E-CPU
python -m unittest discover -s experiments/semantic_neural_compilation -p snc002_tests.py -v
python experiments/semantic_neural_compilation/run_semantic_transit.py --output snc002-report.json
\`\`\`

The GitHub Actions workflow \`.github/workflows/snc002-semantic-transfer.yml\`
does this on hosted Linux. One CI job checks SNC-001 regressions plus
adversarial SNC-002 boundaries, including mTLS wrong-SAN rejection.
A second job uses Python 3.13 to run the actual separate-process TCP
transfer and retains a measured JSON evidence artifact.

### Evidence / trust boundary

- Proven only in the established COE-002 mathematical language:
  exact rational parameters, one input over the real line, ideal
  affine/ReLU arithmetic. No whole transformer, training, float/GPU
  error guarantee, neural improvement or multidimensional extension.
- E-CPU transport is real, but **both local processes run on the
  same physical GitHub host**. No Tailscale/public-internet or
  multi-host independent network test is claimed.
- A same-host test fixture CA provides mutual authentication for
  this session, not independent issuer/source provenance.
- A transferred digest proves consistency under a receiver-owned
  source pin, not an external signature or a trusted author.
- A separate mathematical checker provides certificate-level
  verification, not the later Lean kernel proof chain; this run does
  **not** execute Lean or grant VGI proof/Ground admission.
- A verified reconstructed model is not automatically authorized
  to execute. Actual E-CPU operational admission, quota and effect
  permissions remain receiver-owned future interfaces.
