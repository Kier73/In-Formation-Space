# PGT-002 — Procedural training across partially observed computational Grounds

**Status:** experimental local CPU training, independent finite checks, actual local HTTP model-transfer test. Native E-CPU IOS-001/law-navigator CI gate is specified but not claimed successful until the exact-head workflow passes.

## Why this experiment exists

PGT-001 trained a 20→96→64→9 neural policy from 10,000 complete finite Boolean Grounds. It achieved good sample-level heldout scores, but the 20-dimensional pairwise-relational encoder was constructed from **the complete state table**. When the table is already available, IOS-001 can exactly compute the minimum sufficient measurement set. A model approximating this cheap exact result does not establish increased computational capacity.

PGT-002 makes an intentionally harder distinction: **only 3–7 source states are observed by the neural model**, while a separate offline teacher holds a complete source Ground and its exact intended result. This connects to COG-008/009 partial observations, E-CPU's intention-sufficiency contract, VGI uncertainty, and COG-003's active counterexamples.

## Source families and identity discipline

Four finite generators, each with source-based mathematical semantics:

1. `boolean`: compositions of three Boolean observations and hidden binary distinctions (reuse the original PGT-001 source code).
2. `affine_orbit`: modular affine dynamical systems; observations at declared logical coordinates and target bits at horizons near `10^15`, computed by independent logarithmic affine composition.
3. `http_path`: **modeled** retrieval availability, integrity and permission relations; this family is not a measurement of public HTTP infrastructure.
4. `finite_automaton`: held out **entirely from model training**; binary observations of states propagated through a finite functional graph at future coordinates. This family includes nonpermutations and hidden distinctions not captured by offered features.

The generator parameters and full target maps are never fed to the model. The training encoder receives only 3–7 **queried states**. Its 20 features are the existing permutation-invariant pairwise observation histogram plus advertised symbolic measurement costs and observed-state count. The training objective is the *full Ground's* exact minimum-cost plan or `REFUSE`, so source unobservability creates genuine indistinguishable completions.

Training/validation/test and both held-out automaton sets were separately generated and checked for **zero identical semantic models across splits**, with row-order/source-ID-insensitive Ground digests. Only a 16-/32-state finite snapshot is covered; unseen or adversarial general worlds are not certified by the generator.

## Actual trained parameters and result

Reproduce (Python 3.11+, PyTorch and NumPy) from `experiments/procedural_ground_training`:

```bash
python train_transfer.py --train 12000 --valid 1800 --test 1600 --ood 1400 --ood32 1000 --epochs 28 --repair 180 --output results
python train_hybrid.py --train 12000 --valid 1800 --test 1600 --ood 1400 --ood32 1000 --epochs 28 --output results
```

Actual AdamW optimization of 8,809 learnable parameters produces the content-addressed **`results/partial_ground_student.npz`** (33,907 bytes in the reference run) plus exact encoder/model/teacher manifest and raw metric report. A separate `train_hybrid.py` trial supplies one extra observable input: the exact plan for the *partial* table. Its outcome matched that partial symbolic baseline exactly, and does not justify superiority of neural inference.

| Evaluation | Neural exact plan | Partial-only symbolic plan | Cost-only neural ablation |
|---|---:|---:|---:|
| In-family 16-state, 1600 independent Grounds | **71.8125%** | **74.1875%** | 15.75% |
| Held-out finite-automaton 16-state, 1400 Grounds | **63.1429%** | **62.2143%** | 17.0714% |
| Held-out finite-automaton 32-state, 1000 Grounds | **62.4%** | **61.4%** | 16.4% |

These are advisory predictions only. The model **does not beat** the partial exact planner in-family. Training for more epochs did not solve the fundamental issue: distinct complete Grounds can induce the same partial observations, so no deterministic model can always select the correct hidden full plan.

The model checkpoint uses pinned complete-array SHA-256 and canonical manifest identity, strict tensor keys/shapes/dtypes/finiteness, and independently reconstructed PyTorch inference. No pre-trained weights or GPU were required. The current experiment does not quantify neural-model efficiency against native IOS-001 on actual remote hosts.

## Observation navigation: three evidence tiers

**A. Omniscient finite-reference counterexample teacher (negative/oracle baseline).** A separate complete-domain verifier checks a model's proposed observation set and can return a contradictory state pair. The model sees only the queried pair, never the teacher's complete answer label. On 180 held-out automata, its exact answer increased from **99 to 174** after a mean of **1.033** additional observed states, with 6 still unresolved. Its reference teacher has access to hidden truth and its calls are not free.

**B. Paired active versus random.** On 600 held-out 16-/32-state automata, four new state observations per world after the same four initial observations:

- Neural + reference counterexamples: **580/600** exact versus neural + random: **498/600**.
- Symbolic partial planner + counterexamples: **593/600** exact versus symbolic partial planner + random: **503/600**.
- The symbolic planner outperformed the neural learner under the same privileged counterexample service by **13** cases. Active uses 3,839 reference-teacher query calls across its paired arms. Equal membership-observation count is **not** equal computation or verification cost.

**C. Target-observation-only version space (no complete-reference teacher during acquisition).** Each state's three feature projections are publicly addressable; only that state's target observation is hidden. A declared, 30-candidate Boolean hypothesis class is refined from at most six queried target values. Query selection maximizes candidate disagreement, using only the public coordinates/projections and already acquired answers. On 600 held-out automata:

- Active: **416** correct full mappings; random: **138** correct.
- But active additionally produced **86 incorrect candidate mappings**: functions outside the declared hypothesis grammar cannot be inferred by finite samples.
- The implementation labels these as **candidates, never admitted results**. `receiver_admitted_predictions=0` in the audit.
- Three additional predetermined 1000-case seeds reproduced the active-over-random directional result with full mapping correctness ~70.8%–72.4% for active versus 26%–28.4% for random.

The strong active result depends on **knowing the feature projection for each candidate coordinate in advance**. Without that public Ground structure, unseen state IDs were randomly permuted and no target-informed active query can distinguish an unobserved coordinate a priori. The candidate language is a hypothesis, not a verification class; a trusted whole-domain proof, observed coverage with a justified quotient law, or receiver-held Ground certificate is still necessary before acceptance.

## Real HTTP path and source separation

The transfer test imports the existing PGT-001 `http_artifact_path.py` (itself modeled after PON-003) rather than creating another object protocol. A trained NPZ tensor archive is retrieved from **two actual local HTTP server processes** with a receiver-owned pinned digest. A fresh receiver independently reconstitutes the PyTorch model. Nineteen held-out automaton inputs produce bit-identical logits before and after process-origin replacement. Killing origin A selects B; corrupting B refuses retrieval.

The HTTP server serves bytes; it does **not train or infer**. This does not demonstrate public independent origins, TLS host authentication, passive-link neural arithmetic or autonomous hardware-free intelligence.

## Safety and exact-native contract

A new source class does not confer authority. Even 90%-confidence logits are merely proposals. Finite Ground subset completion and hidden-source truth are different obligations. An incorrect non-refusal would become an unverified execution if admitted directly. A named receiver policy must validate current Ground, observer authority, measurement receipt, horizon, feature domain and source timestamp at realization.

The dedicated workflow checks:

- seeded procedural training, baseline/ablation, hidden-family and semantic-dedup evaluation;
- counterexample and teacher-free active-observation experiments;
- loss and corruption of HTTP origins, fresh-process model reconstruction;
- mandatory **native E-CPU `mailcpu.intention_sufficiency.plan_sufficiency`** comparison over 320 freshly generated cases from all four families, plus `law_certifier.lcg_navigate` at `10^30+11`, using exact pinned native E-CPU sources;
- separate producer/consumer GitHub runners with stored artifact digests and checks.

No native CI success is claimed until the actual exact-head jobs pass. No model recommendation is a replacement for E-CPU's Hypervisor, finite exact planner, Structural Memory certificate, transport evidence or RecoveryLineage authority.

## What to investigate next

Benchmark it against existing exact active version spaces, not only random acquisition.
