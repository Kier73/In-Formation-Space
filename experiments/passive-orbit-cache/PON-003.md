# PON-003 — Surviving-origin navigation through two independently signed publications

**Research question:** when a pure computation is represented by an immutable,
receiver-pinned information orbit, can the observer still realize its verified
mathematical result after one of its independently published *object stores*
becomes unreachable? Can the receiver refuse a corrupted store rather than
substituting an unverified operation?

PON-002 established real HTTPS retrieval from two delivery operators using one
GitHub source. PON-003 separates **publication**, **origin retrieval**,
**mathematical admission**, and **survival under origin loss**.

## Protocol and experiment

The canonical PON-001/CAG-001 root SHA-256 remains:

1345e9576fba37322a92cdf9e48c525c806ba210b389ac9a411ec1923484f229

It names the same five immutable exact-integer operations:

- seed = 3
- left = seed + 4
- right = seed * 5
- merge = left + right
- final = merge * 2 = **44**

Two independently scheduled **GitHub-hosted publisher jobs** each create
their own complete copy of the root and five operation packets, using
different addressing conventions:

1. **Object bucket publisher:** R2/S3-style flat immutable paths,
   manifest.json and objects/{sha256}.json.
2. **Block publisher:** IPFS CIDv1 *raw* blocks, addressed directly
   by the content identifier derived from each complete canonical packet,
   using version 1 / raw codec 0x55 / sha2-256 multihash 0x12 / 32 bytes.

Both publishers generate *distinct*, short-lived Ed25519 keys, sign their
own exact six-object publication inventory and publish only the
signed receipt, public key, and immutable bytes. Private signing keys
remain in memory, are not exported or uploaded, and are not entrusted to
the passive object servers.

A receiver must supply **two separate public-key pins**, an independently
trusted immutable root hash, an epoch floor for each signer, and trusted
current time. The signatures, origin identities, root commitments,
short lease, scope, and individual CIDs must all verify **before any GET**.
It also verifies the publication inventory against the actual trusted
manifest, each fetched SHA-256, each CAG-001 packet's semantic digest,
and all parents. A transport ACK or signed publication claim does not
authorize arbitrary execution effects.

For the default hosted experiment, the two publishers upload their
complete bundles as **separate GitHub Actions artifacts**. The receiver
runner verifies artifact provenance on main, restores the two test
stores into *different directories*, then launches two **independent,
read-only HTTP subprocesses on loopback**.

The two local adapters intentionally implement the same *read-only
retrieval contracts* as a public object bucket and an IPFS trustless
raw-block gateway. They are **not** Cloudflare R2 or a running Kubo IPFS
node. The processes live on the same GitHub Actions worker, and the
artifact archive backend is shared GitHub infrastructure. Consequently
they establish the *failure recovery mechanics* but **do not prove
independent live public storage operators or physically separate hosts**.

### Failure experiment: a genuine process kill, not a changed label

The observer runs four checks:

1. Both servers reachable: reconstruct the complete result **44**
   from the bucket store.
2. Corrupt the bucket's actual root bytes after signing: detect its
   hash mismatch, use the CID-addressed block route, still reconstruct
   **44**.
3. **Actually terminate** the bucket HTTP process and confirm its
   socket is no longer accepting connections: retrieve complete
   information from the other process, still reconstruct **44**.
4. Actually terminate the second origin too: record **unresolved**,
   rather than fabricate a result from unavailable storage or a
   previous cached observation.

At each step, preserve the observed route, exact content address,
integrity decision, result digest, and duration measured *locally at
the observing host*. All arithmetic is realized locally after verified
information retrieval; neither passive server executes the graph.

The independent third-host auditor verifies both publication
signatures, receiver-supplied pinned key identities, all receipt
digests, each reported route phase, and reconstructs the complete
CAG-001 mathematical result anew. On **main**, each publisher
attests its exact origin tarball and the off-route observer verifies
those GitHub workflow attestations before running. The third auditor
also verifies origin and observer attestations and attests its own
independent result. A passing CI test alone is a weaker claim.

## Live public infrastructure: supported but requires provisioning

The same receiver has **strict read-only production transport shapes**:

- Cloudflare R2 public development endpoint:
  https://{authorized-r2-subdomain}.r2.dev/
  with manifest.json and objects/{sha256}.json at the root.
- Trustless IPFS public gateway: https://ipfs.io/ipfs/{raw-cid}?format=raw
  with Accept: application/vnd.ipld.raw, direct raw blocks only.

HTTP redirects, arbitrary off-path URLs, different root identities,
modified bytes, unrecognized codecs, oversized objects, unsigned
publication changes, non-HTTPS public routes, and network success
without complete dependency closure are rejected.

### Provisioning the **two real, independent storage origins**

This experiment does not provision third-party resources using the
repository owner’s account automatically. To execute the true public
origin experiment, the operator must *explicitly* create and control:

1. An R2 bucket, publicly exposed using a distinct R2 development URL.
   Cloudflare documents that r2.dev URLs are **rate-limited and for
   development**, not production; a separately provisioned custom
   domain is appropriate for production use. Upload the exact
   manifest.json and objects directory from a PON-003 bucket bundle
   using the Cloudflare R2 CLI (Wrangler, rclone or AWS CLI), then
   verify the public paths. Do not upload private keys.
2. A Kubo/IPFS node or contracted pinning service with explicit
   persistence authorization. Put **each exact raw byte object**,
   including the manifest, using the raw CIDv1 codec and sha2-256
   hash. For Kubo, the documented command family is
   ipfs block put --cid-codec=raw --mhtype=sha2-256 --pin
   <file>. Check every returned CID equals the published
   signed receipt CID. Confirm the blocks are retrievable using
   a trustless IPFS gateway. A public gateway address by itself
   is NOT a persistent pin or evidence of independent storage.

The raw IPFS block CID for canonical bytes is computed by
pon003_origin.py from 0x01 0x55 0x12 0x20 followed by the 32-byte
SHA-256 digest and multibase base32 lowercase encoding. This follows
the CID specification and allows the recipient to independently
verify the gateway’s raw response. A conventional UnixFS file CID
may differ, so do not interchange them.

The public receiver invocation, once both stores are provisioned,
uses pon003_navigate.py with mode public, explicit R2 and IPFS
endpoint URLs, both trusted receipt files, both separately
authenticated Ed25519 public-key files, and a local output
evidence path. Supplying arbitrary public URLs is not allowed.

A separate, **manual-only** workflow now exists at
.github/workflows/pon003-optin-public-origins.yml.
It requires the repository variables PON003_R2_PUBLIC_BASE and
PON003_IPFS_GATEWAY_BASE to identify the explicitly provisioned
read-only public endpoints. It fails immediately if either is absent.
The runner generates two *ephemeral test receipt signing keys* from
the checked-in source fixture, which are **not proof of ownership of
the external object stores**. It then fetches all six objects once
from the public R2 URL and once from the public IPFS gateway,
requiring both complete results to equal 44 and match in mathematical
digest. If either service is unavailable or differs from the pinned
bytes, the workflow fails. It does **not** perform writes, create
pins, shut down a provider, or assert independently administered
origin identity. Successful public reads alone do not demonstrate
that an origin survives the permanent loss of the other.

Before dispatch, independently upload the exact canonical R2 bundle
objects into the R2 bucket and pin each raw CID using an authorized
IPFS node/service. Use only a small, controlled number of reads to
public gateways; no general provider discovery or broad scanning is
performed. A successful run uploads an attested bounded evidence
report, without treating an ephemeral job-generated signer as external
source authority.

**No production public origin completion is claimed by a local CI
run.** The observer needs actual third-party GET evidence, and the
operator must separately establish control of each publisher and
persistence of its storage. Distinct signed *ephemeral test keys*
are not proof of independently administered domains.

## Remaining theoretical frontier

The information itself may be addressable across network space
while its possible retrieval routes and lease horizons change with
observation time. The observer's navigable state is the verified
dependency closure available at that time, not merely the nominal
objects listed by a manifest.

This suggests a PON-004 question: can we treat placement,
observation, absence, policy epoch and recovery cost as separate
typed factors in a time-state navigation strategy, and select a
provably sufficient set of available descriptions *before* doing
unnecessary transport or computation? A larger typed object
may be the SNC-004 verified model capsule; independently validating
the model would remain the receiving host’s authority.

The current experiment does not claim passive router cycles,
unbounded public storage, independent physical origin survival,
live Cloudflare/IPFS pin evidence, numerical neural inference,
or authorized external side effects.
