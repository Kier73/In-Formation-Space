## Research question

Can a hosted GitHub Actions job request a real short-lived OIDC token, validate its issuer signature against the GitHub public JWKS, preserve only bounded claims suitable for tailnet federation configuration, and have another hosted job independently verify an attestation of that claim record?

IHP-008 validated the source-controlled workflow contracts but could not establish the runtime GitHub OIDC subject. IHP-009 provides observed claim evidence to narrow the remaining administrator setup question.

## Topology

1. The tests job checks redaction, source and run identity, tamper detection, subject classification and attestation policy. Pull requests do not mint OIDC tokens.
2. On main push or manual dispatch only, claims_host obtains an OIDC token from the GitHub runner endpoint for a dedicated diagnostic audience, then validates the RS256 signature against GitHub's public JWKS plus issuer, audience and other bound claims. The bearer and JWT remain in memory; neither is retained, printed or uploaded.
3. Claims_host writes only a bounded list of claims, source context, proof-method description and canonical digest. GitHub attests its exact record bytes and predicate.
4. A separate verifier_host downloads the record and calls GitHub CLI attestation verify, pinning the signer workflow, main ref, SHA-256, predicate and non-self-hosted runner policy. It independently reconstructs the permitted claim context, then attests its report.

The verifier **does not independently reverify the original JWT signature** because the token is intentionally discarded. Its evidence authenticates the GitHub workflow's signature-checked *claim-record statement*. A successful workflow is not evidence of Tailscale authentication, TCP, mTLS, ReliableChannel or E-CPU execution.

## Evidence and limits

This workflow produces (if successful) an artifact named ihp009-signed-github-oidc-claims and a separate ihp009-independent-oidc-claims-report. Both are scoped to the run. It reports actual claims and distinguishes a default immutable subject from a nondefault subject requiring administrative review. Signing keys and token payload are not uploaded.

GitHub independently schedules the claim and verifier jobs, but both remain under GitHub-controlled infrastructure. The independent verifier authenticates the exact claim record and workflow provenance, not the underlying JWT; a malicious producer or compromised workflow can still lie about computations. The live Tailscale and MOR-002 items in [issue #136](https://github.com/Kier73/In-Formation-Space/issues/136) remain pending until independently reconstructed network results exist.
