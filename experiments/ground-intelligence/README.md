# PGI-001 — Procedural Ground Intelligence

A deliberately small research variant of the VL-64 idea: a typed observer accepts intentions, learns a procedural policy from verified feedback, and organizes exact Virtual Grounds as reusable mathematical memory. Unlike VL-I's pretrained-model interpretation, this experiment trains a controller on tasks rather than neural weights. It does not yet generate language, execute arbitrary programs or establish physical host authority.

## Implementation

- `ground_intelligence.py`: contextual proposal policy, typed `Intention`, observe/register, bounded relationship discovery, checked realization, opt-in cold acquisition, cycle discovery and reduction, checkpoint and typed expression.
- `verify_ground_intelligence.py`: independent period reduction qualification, checkpoint replay, expression verification.
- CIG-034A `ground_network` and `ground_network_verify`: reused directly, not copied into the new project. Source-specific CIG Seed admission is reused in the real processor campaign.

The controller's executable and independent checker occupy under 17 KiB together; this is a source-byte measurement excluding the shared kernel, CIG dependencies, interpreter, memory and runtime state. There is no imposed VL-64 64 KiB runtime package contract here.

## Learning and qualification

The shift grammar is the finite tuple -8..8 by default. The contextual policy records attempts n and verified successes h for a context consisting of relative common-period size (same/grow/shrink) and presence of a finite prefix. It orders candidates by (h+1)/(n+2), breaking ties by declared palette order. Failed/unknown attempts affect the heuristic only. The grammar proposes `s=max(0,B.cutoff,A.cutoff-d,-d)` for shift d, checking the shared tail; it is not a complete search of all shifts or earliest cutoffs. The existing independent graph checker must admit each discovered edge. With no offered route, explicit `acquire=True` permits direct exact native rank selection and independent qualification before making that view eligible as memory. A failed budget does not establish impossibility.

A native View is a declared mathematical temporal language. Registering a View alone says nothing about external source provenance. The CIG adapter separately establishes source-specific mathematical qualification. The controller's training policy changes search order, not semantics, and can be adversarial or mistaken without authorizing a false result. The `max_candidates` and discovery work limits apply to the search palette; rank and independent verification have separate per-attempt budgets. `work` counts producer charged discovery/selection operations, not all verification or CPU instructions.

```python
from ground_intelligence import Intelligence, Intention, express, checkpoint
from ground_network import View
from verify_ground_intelligence import verify_expression, restore_checkpoint

agent = Intelligence()
a = agent.observe(View('alternating', (2,), ((0,(1,0)),), 2), memory=True)
b = agent.observe(View('displaced', (4,), ((0,(0,1,0,1)),), 2))
request = Intention(b, 10**900 + 173)
result = agent.realize(request, train=True)
expression = express(request, result)
assert verify_expression(agent.graph,b,request.ordinal,expression)
restored = restore_checkpoint(checkpoint(agent), expected_views=agent.graph.views)
assert restored.realize(request)['time'] == result['time']
```

The expression is structured JSON-compatible data, not a language model. Its checker binds the exact target and ordinal, checks the endpoint selection and replays the admitted route (or independently checks direct acquisition). UNKNOWN is not a definitive proof. Checkpoint restoration reconstructs each immutable view, checks exact identities, independently readmits primitive edges and replays composite provenance in dependency order. Policy counts remain untrusted advice. The digest detects changes, not authorship; expected view IDs can bind a receiver-known source catalogue. No distributed atomicity, external source re-admission, authentication, or physical recovery is implied. A CIG Seed checkpoint has its separate source/anchor admission contract.

## Learning a new invariant from a closed path

For a closed admitted route on A with nonzero displacement d, the composed edge proves A(t)=A(t+d) after a qualified cutoff. Let P be the original common periodic-tail period. Both periodicity and the edge equality imply the tail is invariant under residue translation by d modulo P: choose a sufficiently large representative of each residue, including for negative shifts. The subgroup generated by P and all cycle shifts has generator g=gcd(P,d1,...,dn). Thus g is a valid period of the periodic tail beginning at the *original* cutoff; the finite prefix is retained, not rewritten. Each cycle rank offset obeys hP=dN, with N the count per original period; the reduced count is Ng/P. This does not assert g is minimal.

`discover_cycles` searches a bounded simple-closed-path grammar and independently admits the composite edge. `cycle_reduction` restricts each prime-power CRT coordinate b to gcd(b,g), discards trivial radices, and reduces the MDD nodes. `admit_reduction` separately checks the closed-edge identities, density, period, original prefix and whole-language equality using the existing independent verifier; it registers the new view and a zero-displacement edge only after that check. No enumeration of the original common period is required. Dense/irregular cases may exceed the existing diagram or verification budgets.

## Executed usage campaign

`PGI-001-results.json` is the measured ledger. Each training policy sees 160 generated pulse-language episodes; the contexts correlate with shifts -3 and +5 (90% dominant in each context). Frozen evaluation on disjoint generated source namespaces/residues includes 160 matched, 80 reversed, 40 novel +8 and 40 zero-shift tasks for each of four policies (1,280 verified evaluation requests; 320 training requests across both policies). The domains are synthetic, with held-out task instances rather than novel operator families. Native rank verifies the destinations; source-specific campaign uses separate actual CIG checks. No claim of broad general intelligence or statistically representative real-world workloads.

The nearest baseline wins on zero-shift and global learned wins on reversed/novel; this is a useful reason to keep alternative policies available. The full training cost is charged separately.

The cycle fixture has 15 coprime prime-power coordinates, common period 7,378,677,391,061,896,920, and a three-step prefix. Four independently admitted edges produce two nonzero cycles (30 and 42). The controller discovers both in seven charged graph states and constructs a period-six Ground. For 64 huge ordinals, native selection on the original vs reduced view takes 297,036 vs 1,600 charged producer operations, 51.94 vs 0.52 ms, and identical destinations checked against a direct six-phase formula. Links cost 0.292 ms, reduction/admission 0.192 ms. A 2,878-byte graph+policy checkpoint restores in 0.718 ms. The fixture's true tail depends on two residues; its intentionally oversized common period is not a claim of generic compression. Selection timings exclude independent oracle and graph-recovery costs.

The trained policy is then frozen and used with actual CIG-021/024/029A/034A qualified nonlinear processors. Independent target source, diagram and receiver are built; the original Seed holds eight exact interior anchors; the shifted contracted target starts with an unrelated transient bit. The trained policy sees the original and target Views, not the true shift. All 32 destinations across four sizes agree with fresh independently checked signed rank, marker-level formula and target terminal receiver. The largest old/target sizes are 1,023/346 bits; the shift +5 is found on the first proposal (fixed ascending requires 14), with 4,256 vs 8,591 charged discovery work. Cold target rank+8 queries: 1,013.96 ms; warm Seed execution: 1.20 ms, with original source 763.74 ms, Seed 175.78 ms, target source 106.46 ms, registration 26.84 ms, learned discovery 1.92 ms and additional terminal/oracle audit 540.88 ms. The warm comparison does not include all cold preparation and extra audits. Smallest case favors fresh computation.
