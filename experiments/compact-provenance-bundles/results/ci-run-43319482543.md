## Integrity and provenance

The shared bundle manifest binds common IFS/E-CPU repositories and revisions, toolchain pins, and codec schema registry. Each entry retains source Ground and typed-program digests, dense/sparse model digests, compiler route, interface, verification receipt, codec identity and payload digest. Bundle decoding uses the manifest to reconstruct the original standalone PRC-001 capsule and then invokes the original capsule validator.

SHA-256 provides integrity and identity checks, not author authentication or execution authorization. Verification receipts are replayable experiment evidence, not formal proof certificates.

## Follow-on direction

A better shared bundle needs to reduce the local entry overhead, not only store the common manifest once. The next design should compress or field-pack local per-model headers and receipts while preserving one independently verified manifest, per-entry source/model/codec identity, replay receipt digests, and deterministic byte-identical reconstruction of standalone PRC-001 capsules. It should also retain random access so one realization can be extracted and checked without decoding unrelated payloads.
