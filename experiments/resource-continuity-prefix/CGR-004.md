# CGR-004 — Native Hypervisor execution of an NCR-generated non-affine operator language

**Research state:** reference implementation, CI governed by the accompanying PR. The original E-CPU Hypervisor, VirtualLayerRuntime, OperatorRegistry, HeadlessOS and SAB-003 bounded local subprocess channel remain unchanged. Navigable-Compute NCR-004 and CGR-002 remain the mathematical authorities; source observations are source-reported, not externally authenticated.

## Motivation

CGR-003 proved that a source-witnessed Ground can generate a native E-CPU plan **only after** its transition family is proved to fit the pre-existing IPS-004 finite affine stage language. That is a true integration but not a general finite Ground executor. CGR-004 asks whether an independently qualified *non-affine* source language can execute under an existing E-CPU pure operator contract, without gaining executable-code injection or effect privileges.

## Formal execution contract

1. A receiver pins an ObservedEpoch E and an expected SHA-256 source head in its local storage. NCR-004 admits the deterministic finite transition system, constructs the greatest observer-preserving Moore congruence, builds its quotient operator algebra, and independently verifies the full portable certificate. Missing and contradictory observations refuse.
2. A supervisor selects an allowed host and locally installs a fixed Python subprocess command. **The mathematical description never controls executable code, process argv, host ID or resource policy.** The host is challenged on three source-bound finite word/coordinate pairs. Each returned output is independently checked against the original NCR-004 navigator.
3. The receiver composes a native VirtualLayerWorkload whose input is an exact JSON projection of source head, NCR language digest, admitted initial state, finite word and repetition coordinate. The native OperatorRegistry binds the fixed local handler to a versioned pure OperatorSpec (cgr004.qualified_finite_word). The original VirtualLayerRuntime.execute_operator consults the original HeadlessOS Hypervisor and capability policy *before invoking the handler*. No separate Hypervisor is constructed.
4. Distinct operator requests carry an explicit positive Hypervisor request sequence. The original (source, channel, sequence) replay identity is preserved: exact retransmission may replay its committed result, but reuse of the same sequence with a different workload is rejected as a conflicting execution retransmission. The handler sends one bounded JSON request through the original SubprocessQualificationEndpoint (fixed argv, no shell, strict stdout framing, size and timeout ceilings). The child process **independently** reconstructs the explicit source transition maps and computes the requested repeated word by binary composition on source states, without executing NCR-004 quotient code.
5. The handler checks response schema, correlation digest, response digest, bounded state label and exact agreement with the independently reconstructed NCR-004 result. Only then does it publish a pure native virtual_layer.operator_result. The result explicitly declares effect_authorized false; no IPS-008 APPLY or resource mutation is performed.

For all admitted states s, operation words w and nonnegative logical times k, the requested equivalence is:

    observer(repeated_full_source_transition(s,w,k))
      == NCR004_observe(s,w,k)
      == ECPU_native_Hypervisor_result(s,w,k)

This is an exact finite, stationary source-model statement. Source acquisition, quotient construction, and local endpoint qualification are not magically constant-time. For a precomputed finite map, binary powering takes O(log k) compositions, with O(number_of_states) work per composition. The source transition graph is transported to the fixed worker via pinned local storage, not as executable source code.

## Deliberately non-affine fixture

Six source states (0..5) and two actions:
- cycle: maps 2->3, 3->4, 4->2; leaves others unchanged.
- swap: maps 0->1 and 1->0; leaves others unchanged.

The swap is **not** representable by a single modular-affine map over all six states. The two maps commute and generate a six-operator monoid. Readouts are exact string states, so the quotient contains six classes (this benchmark does not claim state compression). The verified long-time query starts at 2 and repeats (cycle then swap) 10^80+19 times, returning "4".

CGR-003's affine-only lowering must reject the source. The CGR-004 operator must run it through the original E-CPU Hypervisor with both compute rights and an independently qualified native subprocess. The same source is run on a second qualified host with a different local identity, preserving the mathematical result but changing the physical execution receipt.

## Adversarial gates

Tests cover:
- Exact non-affine Ground accepted by NCR-004, refused by CGR-003, accepted by general E-CPU pure operator.
- 10^80+19 time navigation through independent full-state composition.
- Original Hypervisor denial when the requester lacks compute capability.
- Two independently launched and separately qualified local worker host identities.
- Mutating a source law constructs a different NCR processor; a prior host/source qualification cannot be reused.
- Tampered pinned source, incomplete observations, wrong host policy and invalid time/word refuse.
- A false worker output with a self-consistent, rehashed receipt is rejected by the NCR reference oracle.

## Qualifier/authority distinction

The three behavior probes establish only *bounded observed compatibility* with the fixed finite-word ABI; they are not a cryptographically signed host identity, hardened sandbox, or physical host attestation. Any single native process might lie; exact output checking is performed for every operation, not only during qualification. The current tests use local subprocesses on one runner. The fixed worker is intentionally not a general-purpose Python, WASM or shell interpreter.

The operator is **pure**. Mathematical certificates and Hypervisor allowance to run a pure operator do not authorize an external effect. IPS-008 still owns the local protected receiver for actual effects. CGR-004 does **not yet** publish a general-language result as an IPS-005/008 quorum-anchored effect, and it does not prove multi-host loss recovery for a persistent general-language DAG.

## Next specific goals

1. Package qualified finite-language operator receipts as persistent typed DAG stage prefixes, with independent reconstruction from checkpoint bytes on a second executor. Do not reuse the affine-specific IPS-004 checkpoint schema for arbitrary languages.
2. Bind the new source/language digest to original IPS-005 quorum publication and receiver-protected resource policy; use original IPS-008 PREPARE/ACTIVATE/APPLY, never infer authority from the mathematical certificate.
3. Replace the fixed software observation fixture with a source-observation adapter, signed/qualified evidence and explicit epoch renewal; test active query selection under missing transitions.
4. Add a separate actual physical host or independent WAN receiver fault domain, cloned source and credential negative controls, and cost comparisons with ordinary execution.
5. Admit additional languages beyond deterministic bounded finite maps only with independent corresponding proof and execution backends.

## Reproduce in CI

Checkout the pinned E-CPU and Navigable-Compute revisions specified by the workflow, install them in editable mode, and execute test_cgr004_language_hypervisor.py. The workflow also reruns CGR-003 native mTLS continuation so the original effect authority contracts remain intact.
