# RCP-002 — The maximal shared interpretation of a forked continuous intelligence

**Question:** When two interpretations of an environment diverge under copied observer and quorum authority, can we recover a nontrivial, *already learned* mathematical processor without selecting either disputed branch?

**Method:** Compose [VL-I TIME-001](https://github.com/Kier73/VL-I/blob/b8ec6b5edae4845dcb9f3f94e9684da21fc41101/docs/TIME_001_CONTINUOUS_ENVIRONMENT_INTELLIGENCE.md) with the original E-CPU `RecoveryLineageAuthority`, `RecoveryLineageCoordinator`, `RecoveryStateManifest` and `SeedCommitMembership` after RCP-001 proved the effect-receiver common-prefix technique on a genesis-only fork. No new interpreter, neural model or consensus algorithm is introduced.

## Nontrivial fork construction

The source-observed VL-I intelligence is an exact scalar environment with five rational-time observations:

| Time | Observed value | Source host |
| --- | ---: | --- |
| 0 | 1 | source-host-A |
| 1 | 3 | source-host-A |
| 2 | 5 | source-host-A |
| 3 | 7 | source-host-A |
| 4 | 9 | source-host-A |

All source events have exact content digests, strict increasing rational time and the original TIME-001 causal hash chain. The first three points suffice to *qualify* the environment-derived finite mathematical interpreter `x(t)=1+2t` over its sampled epoch. This is not a physical guarantee that unobserved time followed the same law.

An actual E-CPU three-member quorum seals this complete five-observation VL-I checkpoint as **generation one**. We then copy the **real member journal files**, with their original member identities and first committed state, into two independent folders.

Each copy independently seals a **generation-two** E-CPU checkpoint with the same predecessor but conflicting observed histories:

- Branch A: time 5, value 11, host fork-host-A; old law remains consistent.
- Branch B: time 5, value 30, host fork-host-B; the old law is contradicted, starting an incomplete new epoch.

Both locally valid RecoveryLineageCoordinator copies have real generation-two quorum evidence; neither accepts the other's conflicting generation-two head as its latest truth. The fork is *after* the intelligence's acquired interpretation, not at its original genesis.

## The causal meet

Given the two full VL-I snapshots, a source-independent receiver separately pins **both full causal heads** and the environment identity and runs VL-I's existing `verify_temporal_snapshot` over each. It does not trust a summary saying that the histories agree.

The meet is the **longest identical prefix of causal observation-event digests**, not the longest sequence of equal numeric readings. The event hash includes source digest, observation time, observer host, positional index, predecessor head and interpreter identity. Even identical readings from distinct sources or hosts therefore do not silently become the same evidence.

The common section is reconstructed *event-by-event* through an entirely fresh `TemporalIntelligenceGround`, requiring exact equality to the source event certificates. The resulting checkpoint must match an **externally pinned common head** that was retained before the fork. The first empirical processor is recompiled from these reconstructed source events—not copied from the old model's program or asserted by an invalid stale receipt.

The original VL-I `verify_temporal_processor` and `verify_temporal_navigation` then independently establish that the recovered law still has rate `2` and returns the exact rational value `6` at time `5/2` inside the previously observed span, with status `UNVERIFIED_INTERPOLATION`.

This is a general method for exact-prefix sections of VL-I's hash-linked event history, although the chosen fixture has five events followed by one conflicting observation on each side.

## Qualification through original E-CPU quorum

The independent E-CPU proof checker reopens all three journal files in **each** forked copy, obtains the original generation-two proof and high-water, and checks that both head manifests have the exact common generation-one root as predecessor.

A third, **receiver-provisioned** E-CPU quorum is then constructed with:
- the same logical machine identity;
- a different incarnation (2) and owner term (2);
- different member identifiers and fresh journal paths;
- its new genesis bound to the **exact original common generation-one quorum root**.

The new manifest is sealed over the **exact serialized common five-observation checkpoint**. Its state SHA-256 must equal the old source's original generation-one manifest state digest. Both conflicting generation-two manifests must be refused by the independently constructed successor quorum. This is a new trust bootstrap, **not authority automatically conferred by either cloned old quorum**.

The new host restores the original qualified VL-I interpreter from those exact five observations. It then observes a third, distinct continuation: values `20`, `21`, `22` at times 5, 6 and 7. These produce a freshly qualified second epoch with rate `1`, while the original rate-`2` epoch and its earlier source evidence remain addressable under the same persistent intelligence identity.

We do not select the earlier branch A or B; their disputed observations are explicitly discarded as authoritative continuation. Their verified historical contents remain available for forensic analysis.

## Refusals and negative controls

- Forged or missing common checkpoint bytes cannot be reconstructed from an SHA-256 alone.
- A candidate shared prefix with an unpinned causal head is refused.
- Changing an event's observed values and recomputing only an outer digest cannot bypass VL-I's independent event-chain validation.
- Two observations with the *same numerical value but different source-host labels* have different event digests and shorten the causal meet. This prevents flattening observational provenance into mere value equivalence.
- Changing actual E-CPU member journal bytes fails independently reconstructed quorum verification.
- The new membership refuses old generation-two manifests, even though their system ID and mathematical state types are the same.
- The recovered interpreter must reproduce its earlier rate, source observations and typed interpolation before any new observation is admitted.

## What is new relative to RCP-001

RCP-001 tested **resource effect safety** across a generation-one fork with a last common *genesis*. RCP-002 tests **semantic continuity of a nontrivial learned mathematical processor** across a *late* fork in both temporal observations and real E-CPU quorum storage.

The combined result suggests that a persistent intelligence does not need its most recent diverged interpretation to remain operational. It needs the **largest causally admitted and independently recoverable section** of its prior interpretation, and an externally justified new right to extend it. This is one possible operational meaning of navigation in time as restoration of qualified computational structure.

The critical separation remains: this RCP-002 experiment produces an **eligible mathematical interpreter and newly quorum-sealed state**, not any physical or external effect authorization. RCP-001's protected effect receiver is separately responsible for the one tested resource effect. The two protocols are not yet integrated into one atomic cross-repository authority handoff.
