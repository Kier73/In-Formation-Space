# RCP-004 — A source-qualified VL-I Ground through the original IPS-008 mTLS receiver

**Status:** adversarial authenticated receiver-host continuation experiment. The original E-CPU IPS-008 receiver service remains the transport, authentication, ordered handoff, native Ground execution and effect-fencing authority. No new TLS framing, quorum, or independent transport runtime is introduced.

## Previously demonstrated capabilities

RCP-001 established that cloned, separately valid old E-CPU quorum histories cannot be adjudicated by choosing whichever arrives first. A separately protected effect receiver can quarantine both and grant a fresh continuation without choosing a winner.

RCP-002 established that a nontrivial original VL-I TIME-001 exact-rational mathematical interpreter (five observations, rate 2) can be reconstructed from the longest independently verified shared causal prefix after a late fork of actual E-CPU recovery-journal state.

RCP-003 joined that semantic interpreter and a fresh E-CPU quorum into one receiver-owned SQLite effect epoch, with seven hard-crash cuts and an independently verified local effect receipt. It did **not** demonstrate an authenticated resource receiver over network transport.

E-CPU **IPS-008** already provided real mutual-TLS owner/receiver identities, original `SocketTransport` framed messages, response ACKs, native `FencedGroundLineage` generation/host checks, and durable PREPARE/ACTIVATE barriers. The shared-resource question is therefore **not** whether another handoff service is needed; it is whether the RCP-003 semantic relation can participate in that original receiver's effect authority.

## Integration: same receiver database, same transaction

The new `AuthenticatedTemporalIPS008Service` subclasses the original `AuthenticatedGroundEffectService`. It inherits its `serve_once` and all original TLS/framing/ACK logic and delegates original PREPARE, ACTIVATE, APPLY and SNAPSHOT to the unchanged native E-CPU dispatch path. The subclass only recognizes four separately typed, owner-authenticated semantic verbs:

- `semantic_freeze`: reopen all original cloned E-CPU quorum journals, recheck both full VL-I histories and record the qualified five-observation common section in receiver storage.
- `semantic_activate`: independently reopen the NEW E-CPU semantic quorum, check its exact current high-water and source-committed checkpoint, and ask the receiver to install the mathematical context.
- `semantic_apply`: independently reconstruct a navigation from the receiver's protected VL-I source bytes and attempt one local effect under the exact installed context.
- `semantic_snapshot`: read the protected receiver's local state without conferring rights.

A fifth command, `semantic_apply_crash_after_commit`, exists only when the dedicated test receiver has explicitly enabled fault injection. It uses the same normal effect implementation and then calls `os._exit(89)` **after durable SQLite COMMIT but before E-CPU sends its TLS response or sees any ACK**. It is not part of the ordinary service's allowed action set.

The original E-CPU `FencedGroundEffectReceiver` and the RCP-003 `AtomicSemanticResourceReceiver` are provisioned against the **exact same SQLite database path** by one independent receiver OS process. Their tables remain separate: the former owns native `installed_authority` and `effect_handoffs`, while the latter owns the semantic Ground/processor context and `handoff_effects`.

The receiver's independently persisted semantic policy now optionally pins an `ips008_native_guard` with:

1. The exact original IPS-008 native resource path and original mathematical plan digest.
2. The original published source root (which must never authorize the replacement).
3. The required replacement host identifier.
4. The required native replacement assignment epoch (2).

The **same SQLite `BEGIN IMMEDIATE` transaction** that installs semantic effect authority, and each transaction that inserts or returns a semantic effect, independently reads the original IPS-008 receiver's `installed_authority` and `effect_handoffs`. It requires exact published target root, plan, host and epoch, a root different from the old source, and **no pending native handoff barrier**. Because IPS-008 PREPARE, ACTIVATE and every ordinary native effect use that database's same writer lock, a native freeze cannot race past a semantic write that was already admitted, nor can the semantic path start a new effect after a completed freeze.

This is a local SQLite linearization argument, not a cross-network distributed atomic transaction. E-CPU's original IPS-008 PREPARE/ACTIVATE ordering and quorum revalidation still own the network protocol.

## Real-process experiment

The tests import the original E-CPU IPS-005/008 and certificate fixtures, not stand-ins. They construct two independent source histories from an actual VL-I TIME-001 causal Ground and the original cloned E-CPU quorum journals for temporal recovery, plus a separate IPS-004/005 original generated plan. The native first host is qualified through the real `QualifiedStageHost`, E-CPU's receiver-owned Hypervisor and genuine subprocess execution, and the result is sealed by the original native recovery quorum.

The test then:

1. Launches a separate receiver OS process with a real TCP listener and original E-CPU mTLS service, presenting a CA-issued pinned server certificate and requiring the authorized owner's DNS identity.
2. ACTIVATEs the original native published head and commits a native local register effect.
3. Freezes the independently verified RCP-003 common VL-I Ground, and seals a separate fresh E-CPU semantic quorum. Both alone still refuse semantic effects. Attempting to activate the semantic root while IPS-008 still publishes the **old native host** must refuse.
4. Authenticated native IPS-008 PREPARE durably freezes all original effects and returns a barrier ACK. The receiver process is killed without cleanup, then reopened in a new OS process from the exact preserved SQLite database and native quorum journals; the barrier still refuses the old effect.
5. The original E-CPU owner seals the expected next-host assignment, activates its exact quorum root over mTLS, executes the next actual native stage under the replacement host and Hypervisor, seals and activates the resulting published head.
6. The semantic root may be activated only with that exact native post-handoff published root, target host and epoch, and the preserved VL-I source Ground. The local semantic effect is then committed through the **same authenticated E-CPU Message and ACK channel**, with RCP-003 source navigation checked under the same native receiver transaction.
7. The test-only receiver kills itself **after that semantic effect commits but before sending a response**, forcing real TCP response loss. A fresh receiver process, reopened from the same database, must replay the same effect receipt with the same operation ID, and report exactly one committed semantic effect.
8. A subsequent original native IPS-008 PREPARE freezes the receiver a second time. Both new and duplicate semantic effects must now be refused under the native database writer barrier. Native effects from the superseded publication are also refused.
9. A CA-trusted but wrong owner certificate, an incorrect server DNS identity, an invalid native root, or a missing exact semantic successor are all refused.

The independent test also verifies that possessing a mathematically valid source/quorum receipt or a correct mTLS owner identity **does not** bypass the native resource's active replacement-host requirements.

## Scope and falsification

This demonstrates a composable, **resource-local** authority ordering for one original IPS-008 register and one qualified RCP-003 semantic output. All the participating processes (owner, subprocess compute hosts, native mTLS service receiver and original quorum) run on one GitHub Actions runner. It does NOT demonstrate separate physical fault domains, global uncloneable identity, arbitrary mutable external effects, automatically restored physical processes, WAN partitions, Byzantine storage, independent HSM keys, or automatic semantic evolution under every possible environment.

The RCP-003 negative control remains: **cloning the protected receiver database itself defeats global effect uniqueness**. The resource authority is assumed to be independently protected from the cloned computing identity. The mathematical navigation example `t=5/2 -> 6/1` is an **UNVERIFIED_INTERPOLATION**, not a sensor observation; only the receiver-local SQLite log is modified.

No new guarantee is implied for nonparticipating external services. Native IPS-008 already permits a sender to commit a quorum record without PREPARE via other low-level APIs, but the participating receiver refuses that unprepared successor. This bridge does not change that limitation.

## Next frontier

Then inject network partition and credential cloning: distinguish "the TLS connection was authenticated" from "the receiver owns a globally nonduplicated write authority." Source observation continuity alone cannot settle this; additional protected trust must be demonstrated rather than inferred.
