# CGR-003 — An observed NCR-004 Ground becomes an original E-CPU executed and fenced DAG

**Status:** native cross-repository experiment; status of CI/merge recorded on PR. This experiment reuses original E-CPU IPS-004/005/007/008 and current merged Navigable-Compute CGR-002/NCR-004. No alternative executor, quorum, TLS transport, certificate authority or effect database is introduced.

## Problem and qualification path

CGR-002 constructed an observer-relative language from complete, witnessed finite transitions and checked it with NCR-004's independent verifier. IPS-008 independently demonstrated quorum-assigned native affine DAG execution, receiver-owned resource fencing, durable PREPARE/ACTIVATE and mTLS process restarts. Previously, those systems operated on different original semantic Grounds.

Here, a test source reports (before, action, after, before-output, after-output) for every state/action in a finite 17-state system. The source's coefficients are used **only to produce the fixture observations**, not supplied to the Ground constructor. The original merged Navigable-Compute observed-source adapter checks witness closure, source-head identity, native observer equivalence and portable wire verification.

We then ask if the complete observed action functions actually admit E-CPU's existing **finite affine** native instruction representation. The adapter recovers each action's coefficients from observed transitions at 0 and 1, rejects the model unless *all* 17 actual witnessed transitions agree, constructs the exact E-CPU typed primitive palette and source-head-linked ProposedRelation, and calls original synthesize_ground to derive the required executable word.

For the test fixture, the inferred primitive laws are first(x)=(3x+2) mod17 and second(x)=(8x+5) mod17. The original E-CPU synthesis must discover (first,second), whose full effect is (7x+4) mod17. The admitted initial state 9 reaches 12 after stage 0 and 16 after stage 1. Both values must be present in **actual** original Hypervisor-approved, subprocess-qualified, E-CPU IPS-004 DAG receipts, revalidated through original FencedGroundLineage and Navigable-Compute's source Ground.

## Five implementation obligations

1. **Shared Ground**: exact source SHA-256 is embedded as a ProposedRelation Ground identity, while NCR-004's independent mathematical language digest is carried in its verifier obligation. The E-CPU plan digest changes if these scoped identities change.
2. **Ground discovery**: neither affine coefficients nor the E-CPU instruction plan is supplied to the lowering function; they are derived from source observations, and only the verified finite affine family is admitted. Nonaffine, missing and contradictory observations must refuse.
3. **Observer-relative navigation**: NCR-004 independently constructs source operator semantics; the native E-CPU word must render the identical output from the admitted initial condition. This is a finite exact equivalence, not a claim of universal acceleration.
4. **Composable proof**: independent NCR-004 algebra/wire checker plus original E-CPU stage Hypervisor receipt/DAG prefix and quorum high-water are checked before emitting a joint **non-authoritative** publication witness.
5. **Continuous authority**: the original IPS-008 mTLS receiver, resource-local SQLite effect register, native quorum and PREPARE barrier control actual effects. Hard-kill and restart the real receiver after PREPARE; old effect remains frozen, only exact current successor assignment activates; the replacement host executes the second source-derived stage and publishes a valid new root. Its final receiver write must be 16, old worker write refused.

## Process test and falsifiers

The main test starts two distinct original E-CPU subprocess-qualified native computational hosts and a separate OS process that runs the **unmodified** original AuthenticatedGroundEffectService. It provisions actual TLS client and receiver certificates through existing E-CPU tests, operates original recovery-lineage journals and original fixed local SQLite resource.

It checks source/plan digest binding, first native Hypervisor stage receipt 12, first published effect 12, durable freeze, receiver hard kill, native quorum rehome, second actual Hypervisor stage receipt 16, second published effect 16, replay-safe duplicate, frozen old effect and wrong server DNS refusal. A subsequent native PREPARE freezes the newly published result.

It also checks an introduced inconsistent affine witness, incomplete source, changed source revision and tampered persisted source bytes all refuse before native lowering or trusted receiver reconstruction.

The receiver is the **existing native E-CPU IPS-008 service**; the new worker only configures its publisher from the witnessed Ground and launches it in another real process. No new semantic_apply RPC or effect table is created.

## Limits and next experiments

The source is a deterministic *software-generated observation fixture*, not an independent sensor; the finite action vocabulary, state IDs, full labels and affine-capable native backend are assumed. The observer-language result need not compress 17 distinct exact numerical labels. The generated native E-CPU CPU is **the existing affine IPS-004 interpreter** with source-derived primitives, not an arbitrary NCR language virtual machine.

All actors run on one CI machine with separate OS processes and separate local journal/SQLite files. The receiver's source pin and storage are independently provisioned *in the local experiment*, not cryptographically protected against malicious cloning of the full machine or trust roots. Its quorum is the original fixed-term reference majority, not Byzantine agreement or a geographical deployment. No physical actuator, independent WAN host, external signed sensor, neural state, or general nonaffine execution is claimed.

Further:
- Extend the general Ground IR to accept other NCR-004 operator families without coercion into an affine primitive.
- Test partial observations and discover active queries over independently hosted sources.
- Carry a source-qualified identity into the receiver's *own protected policy*, not just a publisher's E-CPU plan digest.
- Test distinct physical fault domains, partitions, cloned credentials and resource-side secure monotonic counters before claiming global effect uniqueness.
- Benchmark costs against direct execution including source acquisition, closure, verifier, TLS handoff and effect commit.
