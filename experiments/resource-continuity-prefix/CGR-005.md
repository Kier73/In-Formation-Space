# CGR-005 — A source-generated non-affine processor with a durable E-CPU execution identity

## Purpose

CGR-004 executes a source-witnessed, non-affine NCR-004 language through the original E-CPU Hypervisor and an independent fixed subprocess interpreter. CGR-003 previously demonstrated native quorum and IPS-008 effect handoff, but only for a finite affine language. This experiment joins the two under the **original E-CPU quorum, DAG, Hypervisor and IPS-008 mTLS/SQLite receiver**.

This is a reference *compatibility adapter* for a deterministic finite language. It is not a rewritten consensus, generic cryptographic proof kernel, untrusted-code execution engine, or independent physical-host deployment.

## Constructed mathematics

The deterministic six-state source reports two total transitions: cycle 2→3→4→2, and swap 0↔1. Exact state labels preserve six observer classes. The source's admitted initial support is all six states to support predecessor-fed execution; each source transition remains explicitly witnessed. NCR-004 reconstructs the quotient and independently verifies the portable mathematical certificate.

CGR-005 constructs an original E-CPU NavigableComputationDAG with two typed dependent nodes. The first stage applies cycle at state 2 and publishes state 3; the second stage **consumes the previously committed output 3**, not an independently supplied starting coordinate, and publishes state 4. Each stage is dispatched through CGR-004's already-verified original E-CPU Hypervisor and fixed subprocess; the second host is independently selected and qualified.

## Checkpoint and original quorum contract

The generalized checkpoint is a new exact schema. It includes the source-head digest, NCR-004 language identity, original admitted SystemIdentity/VirtualGroundRef, stage receipts, each original native Hypervisor effect, and a full original E-CPU NavigableComputationDAG.snapshot.

A completely independent restorer must, without contacting old workers:

1. Verify the separately locally provisioned source head and NCR-004 mathematical certificate.
2. Reconstruct the exact typed DAG node identities/dependencies and observer-relative operator semantics.
3. Independently recompute each stage's expected output from the source *and the previous committed result*; verify host, source, expected output, native Hypervisor operator id, referenced Ground, result digest, original stage receipt digest, and exact DAG commit snapshot.
4. Reject a rehashed false result, missing node, changed source, wrong previous value or malformed receipt.
5. Restore only the latest original RecoveryStateManifest supported by E-CPU's RecoveryLineageCoordinator strict-majority journals; an older hash-valid checkpoint is not authoritative.

The general publisher intentionally implements the original FencedGroundLineage receiver-facing interface while overriding every affine-specific validation/compute/publication method. The original FencedGroundHead and FencedGroundCandidate still represent majority-sealed heads and pure worker candidates. Native E-CPU's content-addressed fsynced artifacts, quorum seal/restore/high-water, stage-fenced atomic publication and existing receiver remain unchanged.

**Important qualification:** this is a deliberately narrow interface adapter. IPS-008's original publisher type assertions currently assume a FencedGroundLineage subclass; this module supplies a typed, fully verified replacement semantic runner. A future cross-repository interface should extract the publisher verifier contract into a generic typed protocol rather than rely on inheritance from the affine-named class. No type assertion alone creates evidence.

## Receiver-owned effects and recovery

The receiver worker launches a genuinely separate OS process hosting original AuthenticatedGroundEffectService and FencedGroundEffectReceiver, mutual TLS, DNS SAN identity checks, original SocketTransport frames and the same independently fsynced local SQLite database across hard process deaths. The client is the original AuthenticatedGroundEffectClient.

The scenario is:

- Qualify and publish stage 0 on original host via original Hypervisor and majority, and receiver ACTIVATE + APPLY value 3.
- PREPARE receiver-side resource handoff to a distinct successor host, fsync the freeze, and verify old effect refusal.
- Kill the receiver OS process after barrier ACK. Restart a fresh receiver OS process, reconstruct source Ground and quorum, and prove the old effect remains forbidden even before the new quorum assignment exists.
- A fresh majority-sealed assignment targets the successor. Receiver ACTIVATE checks exact acknowledged barrier, reopens the original quorum and independently reconstructs the source-qualified DAG. Old effect still fails.
- Independently restart the owner virtual Ground, execute the second dependent stage on replacement host, then quorum-publish it. Receiver ACTIVATE + APPLY value 4. Exact duplicate is idempotent, stale value 3 is refused. A new PREPARE again freezes future writes.

**Authority distinction:** the source certificate and pure Hypervisor effect never publish a physical effect by themselves. The only resource mutation is through the original IPS-008 SQLite receiver under a durable installed quorum root. This is a single local register in one OS runner, not an arbitrary external actuator.

## Evidence and negative controls

The integration tests verify native DAG recovery with no old-worker call, a changed and rehashed false stage, a late obsolete worker whose pure computation can no longer publish, and the actual mTLS receiver hard-kill/restore/effect sequence. A cross-platform CI matrix also reruns CGR-004 and the original E-CPU IPS-008 service regressions.
