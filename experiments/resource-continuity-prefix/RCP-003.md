# RCP-003 — Atomic source-qualified interpretation and resource effect handoff

**Question:** Can a previously qualified, nontrivial intelligence survive a copied-authority fork *and* regain limited effect eligibility through one receiver-authored state transition, across real process crashes at every durable cut?

**Status:** experimental receiver-local protocol. It combines RCP-001's receiver-owned atomic effect admission with RCP-002's original VL-I TIME-001 causal source-Ground reconstruction and E-CPU fixed-membership recovery-lineage quorums. No alternative consensus, original model interpreter, broad code executor or IPS-008 remote effect receiver was created.

## Reason for this integration

RCP-001 tested effect continuity when two cloned original E-CPU quorum histories are both locally valid and disagree. It retained only their original **genesis** as a possible shared predecessor, then used an independently protected local receiver to quarantine both and authorize a fresh successor.

RCP-002 tested **semantic** continuity when the cloned authority fork happens *after* five empirical VL-I observations (1,3,5,7,9 at exact times 0 through 4), which have already qualified the source-derived affine processor \(x(t)=1+2t\). Both E-CPU clones committed conflicting generation-two checkpoint roots after the common quorum-sealed generation one. A fresh observer reconstructed the first five observations and preserved the learned interpreter, without selecting either disputed observation.

The missing link was an **atomic admission relation at the effect destination** between an actual independently checked recovered mathematical processor, the fresh E-CPU quorum that retains its state bytes, and the authority of one resource to accept a write.

A mathematical state reconstruction alone does not grant an effect right. Nor does a quorum proof, independently of the receiving resource's own current admission policy.

## Receiver-owned transition

The new [atomic_semantic_effect.py](atomic_semantic_effect.py) keeps the complete original E-CPU quorum implementation, original source-observed VL-I \`TemporalIntelligenceGround\`, and its original independent temporal snapshot, processor and navigation verifiers.

The new single receiver SQLite database is a **separate protection and failure domain** from the forked authority journal files. Its immutable policy pins:

- the original VL-I environment/interpreter identity and last common temporal causal head;
- the original, independently recovered E-CPU generation-one quorum root;
- the *original* E-CPU membership digest;
- the independently provisioned **new membership** digest for the same logical machine, but a different incarnation, owner term and member IDs;
- the single local demonstration effect resource path.

That bootstrap cannot come from a cloned branch's own claim. This experiment derives it from the source conditions in the test harness and persists it at a separate receiver before handoff. An operational deployment must keep it independently protected and resistant to rollback.

The transition has three receiver states:

\`\`\`text
unprepared (epoch 0)
    | independent original E-CPU six-journal read
    | independent verification of both complete VL-I branch snapshots
    | exact longest causal meet matches receiver-pinned checkpoint
    v
frozen (epoch 1, cannot commit an effect)
    | fresh independently installed E-CPU quorum seals exact common state
    | receiver independently replays both original histories
    | receiver verifies current new quorum high-water
    v
active (epoch 2, exact tuple atomically installed)
    (new quorum root, causal head, original checkpoint digest,
     qualified processor digest, resource effect epoch)
    | local resource operation must present exact tuple;
    | receiver re-verifies source-derived original VL-I navigation
    v
durable receiver-local effect (idempotent operation ID)
\`\`\`

The activation is a **single \`BEGIN IMMEDIATE\` SQLite transaction** updating the entire state record. No effects can be committed while in \`unprepared\` or \`frozen\`. A separate successful new quorum seal is insufficient to thaw the receiver. In the effect transaction itself, the receiver checks the installed epoch/root/context, independently reconstructs the original VL-I processor from its protected checkpoint bytes, re-evaluates the specified historical time coordinate, compares the exact navigation receipt, then inserts the effect receipt under a unique operation identity.

All writes and deduplication happen under the same receiver-local transaction. If a predecessor worker was merely paused, its stale root or wrong context remains ineligible, even after the receiver activates. No global branch winner is elected.

The qualifying navigation has time \`5/2\`, modeled value \`6/1\`, and status \`UNVERIFIED_INTERPOLATION\`. It is **not a physical observation**. The only effect in this experiment is insertion into a local, receiver-owned SQLite demonstration register; this must never be mistaken for authorization to change a physical actuator, payment processor, external API or nonparticipating service.

## Five actual OS hard-crash cuts

[atomic_handoff_crash_worker.py](atomic_handoff_crash_worker.py) is an independently started Python OS process. It uses genuine original quorum journals, durable protected receiver storage, and VL-I's source evidence. Each scenario calls \`os._exit\` with a distinct return code **after** a chosen durable cut, so the process cannot run a graceful cleanup, publish an application-level response, or return a successful effect acknowledgement.

1. **After fork, before freeze.** The source has two locally valid conflicting E-CPU quorum roots but the receiver is unprepared; neither branch can publish an effect.
2. **After receiver freeze, before new quorum seal.** Receiver epoch 1 stays durably frozen. A restarted observer must independently re-verify the real original histories before proceeding.
3. **After new quorum seal, before receiver activation.** The successor has a valid E-CPU quorum root but the receiver remains frozen. A quorum state certificate alone is not a resource capability.
4. **After receiver activation, before any effect.** The receiver has atomically installed the exact new root, checkpoint, processor and epoch. A fresh host can resume without electing an old fork or changing the qualified mathematics.
5. **After effect commit, before acknowledgement.** The original process is dead but the receiver retains one effect under the original operation identity. A new host replays the exact same receipt and must not produce a second effect.

Every scenario is run with an independent freshly constituted original and successor quorum, original five-source-observation VL-I interpreter, hard-crashed worker and fresh reopening of the receiver. The parent must observe the expected durable receiver mode **before** recovery, then complete all remaining stages, check duplicate retry, and refuse both original cloned roots.

Each cut is **after a stage's successful durable commit**. The experiments do not yet interrupt a SQLite transaction *mid-write* or an E-CPU quorum *mid-prepare/commit*. SQLite's transactional atomicity and E-CPU's existing partial-commit retry contracts are reused rather than re-proved by this runner. That narrower claim is important.

## Strong refusal and falsification cases

- A genuine new successor quorum root **without** an independently verified receiver freeze does not activate effects.
- A receiver frozen at an exact source and causal prefix cannot be activated by an unsealed or mismatched E-CPU proposal.
- A rehashed/tampered VL-I snapshot cannot be substituted: full branch bytes must match the originally quorum-sealed state digest, each source event is replayed with original TIME-001, and the source meet is independently recalculated rather than accepting an untrusted supplied \`meet\` record.
- Original E-CPU member journal tampering is rejected on independent quorum replay, including after a valid freeze and before receiver activation.
- A mathematical navigation claim with substituted values, wrong context, wrong resource epoch or either original branch root cannot commit an effect.
- Concurrent duplicate local effect requests produce exactly **one** atomic receiver effect record, with stable receipts. Reusing one operation ID for a different yet mathematically valid navigation is refused.
- **Deliberately clone the protected receiver SQLite database:** the two clones can commit divergent effect histories. This is a negative control against any claim that the method establishes globally unique authority when its trust anchor can also be copied.

No claim is made of HSM/TPM identities, uncloneable quorum keys, physical sensor attestation, time-continuous observation of unobserved intervals, geographically separated authorities, Byzantine safety, cross-resource atomicity, or automatically generated authorization.

## What becomes possible

Within the stated single-receiver trust model, the experiment gives a *joint* and checkable continuation relation:

\[
\text{Qualified causal Ground}
\;\land\;
\text{fresh E-CPU quorum root}
\;\land\;
\text{receiver-owned effect epoch}
\;\longrightarrow\;
\text{one admitted local effect}.
\]

The **processor's mathematical identity** persists at the longest independently verified shared observation section. Its **permission to alter a specific resource** is a new and separately installed receiver relation, not a historical possession of code or old certificates.

The two original branches remain preserved as **conflicting historical evidence**. Neither becomes the chosen future merely because it finished earlier, had the same keys, or produced a plausible numerical result.
