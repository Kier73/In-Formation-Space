## Sparse same-tick seek

The runtime emits three events at logical times [1, 1, 2]:

1. Step to tick 1.
2. Model revision at the same tick 1.
3. Step to tick 2 and state 10.

The trajectory has frame indices [0, 1, 2] but its default stride 64 indexes only the earliest frame. The seek bridge first uses that sparse index, then scans forward through subsequent frames that share the exact requested logical time. It therefore returns:
- Seeking tick 1: revision event, trajectory frame sequence 1, runtime event sequence 2.
- Seeking tick 2: step event, state after [1, 0].

This is stronger than the earlier stride-one proof: the revision itself is not indexed, yet the seek returns it as the last event at tick 1.
