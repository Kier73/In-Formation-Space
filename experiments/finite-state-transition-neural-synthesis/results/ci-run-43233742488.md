## What the bridge adds

E-CPU's new stateful transition trajectory module exports committed runtime events through the existing TrajectoryWriter, projects those same event payloads into EventJournal, and restores the runtime only after all three integrity views agree:

1. Original runtime event chain.
2. EventJournal projection chain.
3. Binary trajectory receipt chain plus the manifest digest.

The binary frames preserve runtime events intact. Each frame's logical time is the resulting tick for a step and the unchanged tick for a model revision. Thus the three-event history is stored at logical times:

step(tick 1) → revision(tick 1) → step(tick 2)

A separate sparse logical-time index supports seek after verifying the trajectory receipt chain.

## Same-tick revision seek

This is the key result: seeking logical tick 1 returns the **revision event**, not the step immediately before it. The trajectory frame index is zero-based, so it is frame sequence 1; the embedded runtime event sequence is one-based, so it is runtime event 2.

| Logical tick sought | Returned event | Trajectory frame | Runtime event |
|---:|---|---:|---:|
| 1 | revision | 1 | 2 |
| 2 | step to state 10 | 2 | 3 |

This confirms that the model revision is represented as an ordered event at the same logical time coordinate, rather than being artificially assigned a new tick.

## Limits

The binary trajectory and index are separate files, and the manifest is a third file; this is not a transactional distributed store. The manifest digest and receipt chains need a trusted head to provide integrity. They are not signatures or an external trust anchor. The bridge serializes already-committed runtime events and does not authorize unverified state mutation.
