## What changed in this experiment

The transition rule is no longer entered as a manually authored table. It starts as a typed Boolean program consisting of input, constant, NOT, AND, XOR, and SELECT nodes. The compiler evaluates this program over the complete 16-row domain to construct a finite table. Separate compiler paths then generate:
1. ReLU minterm weights from the complete table.
2. A MailCPU reference program from the table's conjunctions of input literals.
3. A second ReLU model directly from the typed Boolean expression DAG.

The one-row semantic override is also composed in the typed AST, independently enumerated into a target table, and checked against a direct table-row edit before model construction.

## Interpretation

The direct compiler reproduces the transition function without assigning one hidden unit to every truth-table row. For the baseline counter, its 54 active parameters are fewer than the minterm models' 84 and 100, though its dense parameter count (335) is between the two minterm layouts (114 and 386).

The edited typed program has a much deeper expression graph because its one-row guard must be represented in the Boolean algebra. Its dense compiled model therefore grows to 1,678 parameters and 130 active parameters. Compositional compilation is not automatically a compression strategy: the AST shape, feature lifetime, and dense identity-carrying layers affect cost. This is a useful measured limitation, not something hidden by the exactness result.
