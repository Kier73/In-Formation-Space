## Stateful runtime lifecycle

The runtime begins at state `01`. It holds for one step, then accepts a compatible transition revision without changing state or logical tick. The next `advance=1, reset=1` input uses the revised rule and moves the state to `10`.

The three-event history is `step → revision → step`. Snapshot replay is identical, and modified event history is refused. VGI and both MailCPU interpreters agree with the runtime's neural result.

## Evidence boundary

The generated corpus is finite and seeded; it is not a proof over every possible Boolean AST. The counter transition is exhaustive over its 16-row Boolean domain, and the recurrent experiment exhausts all three-step control sequences. The stateful revision test is one declared lifecycle scenario. No arbitrary real-valued generalization, learned model behavior, distributed/durable runtime, external signature, or physical vCPU performance is claimed.
