## Capsule format

The capsule framing is:
1. 8-byte magic \`IFSPRC01\`;
2. framing version and header length;
3. canonical JSON metadata header;
4. exact inner codec payload.

The header carries source Ground, typed program, dense/sparse model, compiler route, interface, codec schema, toolchain revisions, payload digest/length, and a verification receipt. Three integrity identifiers are used: capsule identity digest, header digest, and payload digest.

The format binds data and evidence together, but it does not authenticate an author or authorize execution. The receipt is replayable experiment evidence, not a formal proof certificate or signature.

Across all 288 capsules together:
- inner model payloads: **652,349 bytes**;
- capsule metadata/framing: **724,460 bytes**;
- complete capsules: **1,376,809 bytes**.

Metadata/framing overhead averages approximately **2,515 bytes per capsule**. It is therefore greater than the inner payload for the compact binary encodings. Row-mask binary produces the smallest aggregate capsule set at 185,573 bytes; hybrid binary is close at 187,398 bytes. CSR binary is larger at 210,861 bytes.

This is a direct discovery from PRC-001: including sufficient portable provenance and evidence can outweigh the storage gained by compacting the realization itself. The next research increment should reduce or structurally share this repeated metadata without weakening the binding between payload, source, interface, and verification receipt.

## Verification boundary

This run establishes complete finite-domain replay for the selected workloads and exact E-CPU sparse encodings. It does not establish correctness for arbitrary models or continuous-valued domains. The capsule format is not yet integrated into E-CPU communication, admission, durable session storage, or remote execution. SHA-256 supplies integrity and identity checks, not origin authentication or authorization.
