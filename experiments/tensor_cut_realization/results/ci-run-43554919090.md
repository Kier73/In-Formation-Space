Every numerical request and application response crossed an actual E-CPU `SocketTransport` + `ReliableChannel` stream protected by reciprocal TLS; GitHub artifact files did **not** relay the operation or partial output between these local processes.

A third request to worker 0 carried a mismatched manifest digest and was rejected by receiver-owned policy. ## Unresolved frontiers

This **does not** establish a general E-CPU `TransitComputeWorker` / VirtualLayer/Hypervisor tensor backend, source-publisher cryptographic authenticity, a durable exactly-once replay protocol, real inter-host Tailscale execution, end-to-end physical network metrics, full GPT-2 inference, or any accelerator speedup. The four independent worker **processes** share one CI runner and its root trust bootstrap. The pinned input identity is the two-probe TCR-001 test input; supporting new activations requires a correspondingly new observation and reference policy.

The next discriminating experiment should put these typed operations into destination-owned E-CPU operator admission and durable session/recovery authority, with real separately hosted peer connectivity and independently reconstructed cost spans. Preserve the same cut and numerical reference evidence boundaries.
