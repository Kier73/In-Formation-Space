# AKS-003 — Quorum-anchored causal-attention state across abrupt receiver loss

**Status: experimental; semantic checks locally evaluated, native E-CPU process and Hypervisor gates require successful pinned CI.**

## Question

Can the entire 3-layer × 3-head exact finite-field attention state from AKS-002 be restored after the **observer-host process is hard-killed** using E-CPU's *already implemented* M1 immutable state objects, M3 computational sessions, three-member durable recovery-quorum lineage, and local Virtual Layer Hypervisor admission—**without replaying 73 previous token observations in the replacement receiver**?

The experiment deliberately does not develop a second recovery authority, DAG, KV cache, Structural Memory law family, neural engine, or consensus protocol. It uses:

- `mailcpu.computational_objects.ComputationalObjectStore` as the existing domain-neutral M1 immutable object plane, with a small filesystem-backed **test page backing** (256-byte SHA-256-addressed pages, write/fsync).
- `mailcpu.computational_session.ComputationalSessionStore` as the current-state authority and revision compare-and-swap interface. The complete AKS-002 compact checkpoint is encoded as canonical JSON state bytes, not reinterpreted as a scalar law.
- `mailcpu.recovery_lineage.RecoveryLineageCoordinator` and `RecoveryLineageAuthority` with **three separate fsynced member journals** and a strict-majority recovery certificate. The same independent quorum high-water is re-opened after the process dies.
- The existing `mailcpu.HeadlessOS`, seed admission, `OperatorRegistry`, `VirtualLayerRuntime`, capability checks, and Hypervisor arbitration, on the replacement receiver only, to authorize a **pure, non-mutating query** of the recovered state.
- AKS-001 and AKS-002 unchanged for source receipts, exact prefix moments, multi-layer/head causal updates, and independent direct-history oracle.

## Experiment chronology

1. A supervisor launches receiver **A** as its own Python interpreter. It creates a three-member E-CPU RecoveryLineage quorum, a real M1 object store, a real M3 session, and a 3-layer × 3-head attention Ground.
2. A observes 73 synthetic source tokens, validates the complete prefix with AKS-002 independent-history verification, then CAS-commits the canonical compact state. Each page is content-addressed, and M3 persists and quorum-anchors revision 2. A exports its typed checkpoint/lineage proof and fsyncs an observation marker after commit.
3. The supervisor confirms A is still running at that durable boundary, calls `Popen.kill()`, waits for a nonzero exit, and launches a fresh Python interpreter for receiver **B**. There is no voluntary shutdown, process snapshot trick, or in-process object reconstitution.
4. B opens a **different host session directory**, reopens the three preexisting fsynced authority journals and same page storage, and refuses the transferred export when using a different backend fingerprint without explicit compatibility policy. It then accepts the **explicit schema-scoped A→B compatibility** policy after verifying the quorum high-water and full M1 page integrity.
5. B reconstructs the AKS-002 sufficient state from only the exact M3 bytes. It **does not re-read the first 73 source-token receipts**. It constructs a fresh HeadlessOS, admits its own Virtual Ground, declares and binds a trusted local pure `aks003.attention_probe` operator, refuses an invocation lacking the `compute` capability, and accepts an authorized query pinned to M3's exact checkpoint digest and revision.
6. B appends one token (`index 73`), CAS-commits revision 3 through M3, and verifies that an exact retry from the old revision returns the same revision with `replayed=True`. An old revision-2 export is rejected after revision 3 becomes current.
7. The **supervisor**, not B, independently reconstructs 74 source inputs and executes quadratic per-token neural observation. It compares both the non-mutating probe at revision 2 and the appended token's exact output and final source/state fingerprints.

## Falsifiable gates

| Gate | Refusal or expected observation |
| --- | --- |
| Unauthorized Virtual Layer compute | DENY, local handler calls 0 |
| Authorized post-restart Virtual Layer query | ALLOW, local handler calls 1, result agrees with direct-history oracle |
| New backend without explicit compatibility | Refuse before state restore |
| Missing or modified M1 page | Refuse before interpreting state |
| Stale revision-2 export after new quorum revision | Refuse; high-water cannot roll back |
| Exact same session transition retried | Same checkpoint digest, `replayed=True` |
| 73-token historical replay in replacement B | 0 historical source reads; compact state only |
| Earlier mathematical state and new state | Independent oracle and pinned source/state hashes agree |

## Important distinctions

- E-CPU's `StructuralMemoryRegistry` is currently an **admitted scalar generator registry** (int, LCG, GF(2), finite graph) rather than an arbitrary-attention tensor store. AKS-003 **does not invent a fake generator** to pass its whitelist; M3 was designed for domain-neutral session state. Its Structural Memory registry remains separate, available for its actual admitted laws.
- The three authority journals are **separate durable logical members on one local filesystem**. This is a true E-CPU quorum **protocol**, but not a three-physical-host failure-domain test or an authenticated TCP/Tailscale remote recovery demonstration.
- A dies through an actual operating-system process termination. Durable filesystem state remains. The test does not prove survival of a disk/controller failure, untrusted storage replacement, or physical host destruction.
- The trusted local operator handler receives the M3 snapshot only after requesting fresh quorum high-water and matching the caller's revision/checkpoint digest. Virtual Layer admission is not a replacement for M3 current-state selection, and M3 checkpoint creation is not a replacement for Hypervisor execution authority.
- The finite-field affine kernel is **not equal to exponential softmax**, nor to pretrained Qwen/GPT transformer KV state. No softmax equivalence or general LLM acceleration is asserted.
- Synthetic input creation still requires one update per token during the initial observation. **Post-checkpoint query and continuation** do not replay the historical source stream.
- SHA-256/content-addressed bytes and local journal majority are integrity and recovery evidence, not third-party signatures or attestation of actual network origin.

## Reproduction

On branch stacking **AKS-001 → AKS-002 → AKS-003**:

```bash
python -m pip install 'git+https://github.com/Kier73/E-CPU.git@6fd416facdb2aefd6fc7d66a06b014e3d31b5a52'
python -c 'from mailcpu.computational_session import ComputationalSessionStore; from mailcpu import VirtualLayerRuntime, HeadlessOS; print("native import ok")'
python -m unittest discover -s experiments/attention_ground_sufficiency -p 'test_aks003.py' -v
```

Two Python versions (3.11 and 3.13) run in the repository's dedicated AKS-003 GitHub Actions matrix. The native import step is mandatory there; no native checks may pass by skip. The pure mathematical tests run independently even in environments lacking E-CPU, but must **not** be represented as passing the hard-kill/Hypervisor gate.
