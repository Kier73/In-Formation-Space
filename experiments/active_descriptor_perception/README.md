# CLT-011 — Active descriptor perception for the Virtual Layer Machine

Pinned tandem source: IFS VLM-001..006 PR #383, commit a1b3a88349b7624de140d12d29685a79305d1266. Its native neural selector has six lossy graph features; the recorded 1000-graph evaluation found four feature classes, two conflicting, 825 maximum retrospective classifications and 817 neural predictions. Exact native discovery was faster in that recorded timing pass. This experiment targets feature sufficiency, not a claimed speedup.

Train a bounded active sensing tree per coarse feature vector. The training source generates word-DAG descriptors with construction labels (affine, canonical nonlinear chart, unsupported). No chart-specific relation is provided to the learner. Offer 272 Boolean literal predicates from the first 16 descriptor slots: zero/aligned, equality/opposite modulo 2^32. Each predicate requests one or two descriptor fields; subsequent choices are conditioned on earlier observation. Greedily select the greatest reduction in unlike-label pair count divided by declared field cost. Stop at a pure training leaf, depth three or no useful split. The model records a proposed Ground kind only, never mathematical admission. Descriptor access includes the node kind and literal as one abstract read; coarse feature scanning, graph staging, grammar construction, training, allocation, hashing and verification costs are not measured in these read counts. Training predicate calls separately recorded.

Baseline is majority label by existing six-feature vector; held-out cases use a distinct PRNG seed but the same deliberately structured generator. The challenge alters a different node in canonical charts without changing the discovered literal relationship; these can pass perception and must be rejected by exact admission. No general inference or accuracy guarantee. Local JS execution uses separately generated construction labels and simulated admission counts, not native C outcomes. Native replay calls actual VLM graph_features, discover_active, try_ground_kind and fallback, verifies generated labels and all proposed admissions, and is registered in CI against the pinned VLM tree. This gate has not executed in the authoring runtime.

The sequential policy is a small active acquisition tree, not a recurrent model or a general partially observable control solver. The additional sensor predicates form a declared grammar (not unrestricted sensor invention). The intended native action remains exact verification; on zero proposal or refusal the original exact discover_active is called. No incorrect admission can be justified by a classifier output. Future: use conflict certificates to refine the tree, charge actual native descriptor scan and verification costs, compare against direct discovery, then qualify sensors over real application tasks.

Reproduce local results: `node experiments/active_descriptor_perception/clt011.js`. Native integration: build pinned native64/libcore.so and run `python experiments/active_descriptor_perception/native_check.py /path/to/native64`. No bare-metal or physical E-CPU execution asserted.
