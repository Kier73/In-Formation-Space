# IWI-004 — Evidence-directed Ground construction without epistemic escalation

**Date:** November 15, 2026. **Status:** synthetic finite research implementation, not physical Ground admission.  
**Question:** Given an intention that is not guaranteed across an incomplete law, **which authorized additional evidence would make it realizable**, and how can we prevent an authenticated single observation from falsely becoming a universal law?

This extends [IWI-003's fixed but incomplete Ground planner](IWI-003.md). The central result is about **quantifier order and provenance**, not claiming to invent model-based active learning or contingent planning. In particular, no single signature or successful sample demonstrates complete transition coverage.

## 1. Experimental result: acquire exactly what the intention requires

We reuse the seven-state IWI-003 model whose unknown, fixed transition cell is \`t:0:1 ∈ {2,3}\`. Under an erased diagnostic observation, the **global** two-completion oracle proved that no observation-based execution policy can guarantee state 0. Both individual completed laws nevertheless have a two-action winning path.

**IWI-004 does not guess the cell.** It is given a catalogue of *hypothetical* pre-execution capabilities that reveal the exact stable value of a specific cell for the actual persistent law. A capability is typed \`offline-static-law-cell\` with a **positive symbolic cost**. Such an oracle is a strong external assumption, deliberately different from an ordinary observed transition.

The acquisition planner performs an AND/OR search: for each permitted cell query, it must succeed after **every** possible returned value. At each answer branch it reuses the IWI-003 fixed-law planner and its existing exact execution policy. It minimizes the worst-case sum of query costs, with a separately written query-choice oracle validating the minimum.

| Experiment | Result | Exact cost | Post-acquisition guarantee |
| --- | --- | ---: | --- |
| Erased diagnostic, request \`t:0:1\` allowed | **REQUEST_LAW_EVIDENCE** | **2** | 2 execution actions, for either returned value |
| Same Ground, no permitted acquisition | **UNRESOLVED_WITHIN_DECLARED_BOUNDS** | — | No policy for the declared query and execution horizons; the separate small global oracle proves this particular no-acquisition case impossible |
| Five-action in-execution diagnostic retained | **READY** | **0** | 5 execution actions, no additional law request |
| Shared one-action reset and 24 irrelevant unknown cells | **READY** | **0** | 1 action; no relevant-law queries required |

The query costs are synthetic units, **not time, network RTT, energy, or a claim about an actual receiver's available API**. Every possible returned value is treated adversarially for the worst-case guarantee.

One conditional law query at cost 2 converts the unobservable example into a two-action realization, but only **if the query is actually answered by an authorized correct static-law oracle**. The mathematical planner never claims that such an oracle exists.

## 2. Two separate gates: planning and evidence admission

The acquisition plan **does not itself admit evidence**.

\`evidence_claims.js\` handles an exact signed JSON envelope binding:

- immutable model SHA-256 / context / revision;
- issuing key ID and caller-pinned Ed25519 public key;
- cell key, value, request ID, fresh nonce, and claim class;
- caller-supplied trust policy specifying exactly which cells that issuer is authorized to certify as **complete static law values**.

A cryptographically valid \`sample\` claim is retained as a signed measurement but leaves the Ground **unchanged**. An \`law-cell\` claim is eligible only if the *external trust policy explicitly grants that issuer complete-law coverage for that exact cell*. After checking the signature, model/revision/context, cell domain, per-invocation nonce replay, coverage permission and cross-signer contradictions, the gate returns a **proposed** narrowed Ground. It never calls VGI Ground admission, E-CPU VM execution or a physical actuator.

If authorized signers disagree, or a request/value/domain is forged, the gate **refuses the entire revision proposal** without choosing one signer or rewriting the original Ground. The authentic credential and its truthful reporting are deliberately independent assumptions.

**Important:** Neither an Ed25519 signature nor a trusted-coverage *label* proves a source is honest or that its law actually remains invariant. The coverage entitlement is an explicit, externally provisioned premise. This experiment illustrates the protocol distinction; establishing physical coverage requires a separate verification method.

The replay check is limited to **one invocation's bundle**. No durable anti-replay, key rotation, revocation, hardware-root attestation, or independent trust federation is claimed.

## 3. Read-only, source-aware GCI-004 / GCI-005 bridge

The existing IFS [GCI-004 receiver fabric](../cross-ground-continuity/gci004/README.md) already uses real E-CPU mTLS sockets, ComputationalPeerSnapshot and ephemeral EC certificate keys. Its signed feature receipts are built with \`gci004/fabric_contract.py\`, signing canonical sorted-key UTF-8 JSON using **ECDSA-SHA256**. [GCI-005](../cross-ground-continuity/gci005/README.md) demonstrates that two differently authenticated receivers can sign mutually contradictory values; signing identifies a key, not truth.

\`gci_sample_bridge.js\` implements a **restricted, independent Node.js verifier** for the ASCII, safe-integer subset of that exact payload format. It recomputes the original canonical request SHA-256, checks the peer, feature, snapshot digest, task, challenge, phase commitment and binding, then checks an ECDSA-SHA256 receipt signature against a **caller-pinned EC public key**. It returns **SIGNED_FEATURE_SAMPLE_ONLY** with \`entailsUniversalTransition=false\`, and never produces a narrowed model. Wrong keys, request substitutions, modified feature values and noncanonical signatures are refused.

The bridge does **not** validate the X.509 CA/leaf trust chain, TLS transcript, GitHub attestation or actual receiver's phase. Those checks are implemented by the existing GCI-004 independent auditor and must remain separate, especially when using real receipts. No previously captured GCI-004 receipt has been falsely represented as a new live observation here; tests use ephemeral locally generated EC signing keys. Even an authentic real GCI receipt is a **feature sample**, not an exhaustive static transition law-cell oracle.

Source implementation was **studied, not copied**: [GCI-004 canonical receipt contract](https://github.com/Kier73/In-Formation-Space/blob/6c0d42b4c6cbf5d5fcf9629f6762f822f847c08a/experiments/cross-ground-continuity/gci004/fabric_contract.py) and [CAG-004 canonical digest](https://github.com/Kier73/In-Formation-Space/blob/6c0d42b4c6cbf5d5fcf9629f6762f822f847c08a/experiments/convergent-ground-fabric/cag004/contract.py). Node canonicalization intentionally rejects Unicode, floats and unsafe numbers outside its verified subset rather than silently re-encoding them.

## 4. Reproducibility and proof obligations

Files:

- \`evidence_acquisition.js\`: exact bounded search over **licensed perfect offline law queries**, plus independently enumerated optimum/counterexample verifier;
- \`evidence_claims.js\`: Ed25519 signature/coverage/nonce/conflict refusal gate; proposal only;
- \`gci_sample_bridge.js\`: read-only P-256 GCI receipt verifier, no promotion to transition coverage;
- \`test_evidence_directed.js\`: optimality, independent complete-law check, unauthorized acquisition, forged planning reports, signed samples, correct coverage, conflicting valid signatures, changed context and replay;
- \`test_gci_sample_bridge.js\`: native Node ephemeral EC P-256 signing, exact canonical request binding, tamper and wrong-peer rejection;
- \`results/evidence_acquisition.json\`: deterministic exact mathematical witness, without test signing keys.

From the repo root, Node.js 20+ (standard library only):

~~~sh
node --test experiments/intention-without-identification/test_evidence_directed.js experiments/intention-without-identification/test_gci_sample_bridge.js
node experiments/intention-without-identification/evidence_acquisition.js
~~~

The Linux/Windows × Node 20/22 workflow runs these and all earlier IWI regression groups. Tests generating ephemeral signing keys are **not deterministic byte-for-byte receipts**; the mathematical result file is deterministic. Actual hosted status must be checked rather than inferred from test definitions.

**Mathematical soundness:** The query tree branches on every possible value of each selected static-law cell. Restriction of a domain is conditioned on the query's perfect oracle premise. Each ready leaf contains an independently verified IWI-003 execution policy that succeeds for all remaining compatible complete laws. By induction down the query tree, for any original complete law, following its true oracle answers reaches a leaf whose policy guarantees the intention. The query-cost recurrence adds the query's symbolic cost to the worst-case cost of its children. Enumerating all admissible choices produces the minimum worst-case cost within the declared budgets. A refusal is only about those **declared execution/query horizons, scopes and capabilities**, except where the separate complete-law global oracle explicitly proves unbounded refusal for a small fixture.

## 5. Next frontier: evidence that merits law coverage

The research task now is **not to attach more signatures to samples**. It is to specify and verify circumstances under which a receiver's evidence warrants a *stable law-cell* claim: exact observed pre-state, controlled action, full coverage in a declared finite Ground, invariant environmental context, repeatability after recovery, independently checked source logic, and the scope in which the law may be reused.

That requires making the transition from a test oracle to E-CPU/VGI native evidence and authority deliberately. A cryptographically signed contradiction must remain disagreement; a missing sample must remain unknown; and a verified restricted context must **never be promoted to a universal law**.
