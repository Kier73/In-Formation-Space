# IWI-006 — Authenticated receiver to VGI observation Ground to E-CPU quorum recovery

**Research date:** November 15, 2026. **Status:** native-system integration committed, hosted checks pending. This is a reuse of existing capabilities rather than a new evidence authority.

## Discovery

The key implementation already exists. GCI-004 supplies E-CPU computational-fabric discovery, mutual TLS and signed observer receipts. GCI-005 adds a second distinct signing observer and intentionally false signed reading, verified without the hidden phase by its independent honesty_contract.py. VGI already has ChannelExchangeLedger, EncounterLedger, TransportFrameReceipt, TransitionEvidenceLedger, explicit QUORUM / AUTHORIZED finalization and partial Ground reconstruction. E-CPU SAB-007 already includes an fsync content-addressed evidence store; E-CPU RecoveryLineageCoordinator already provides fixed-membership majority-sealed state roots, anti-stale generations and durable journals.

The IWI-006 work is the *semantic adapter* between those components.

## Evidence semantics: authenticate first, then interpret

The GCI-005 report contains authenticated **feature readings about a withheld phase**, not a verified transition law. The adapter invokes the original GCI-005 phase-blind X.509 and ECDSA report verifier BEFORE VGI interpretation. It requires caller-pinned source and Ground identities, upstream GCI-004 network report identity and the two test CA identities.

Each of the two GCI-005 rounds becomes a new VGI **request-scoped observation-event Ground**. Its initial state is the exact measurement request and challenge, its observation action is observe.parity and its reported output is the signed bit 0 or 1. This is deliberately not a reusable physical phase-transition law.

For both receivers in each round the adapter creates a native ChannelMessage and Encounter with provenance bound to the hash of the *original* signed GCI-005 receipt. Native VGI TransportFrameReceipt.capture is used only for the **offline import** message. It is not falsely described as the original E-CPU SocketTransport frame. The actual source signatures and certificates stay in the sealed source report and are reverified on recovery.

VGI's actual strict two-source policy must reproduce:

| Source round | Before finalization | Finalized status | Admitted observation edge |
| --- | --- | --- | --- |
| Two matching authentic signed readings | QUORUM | AUTHORIZED | One request-scoped observation edge |
| Two authentic but contradictory signed readings | CONFLICT | CONFLICT | None |

Both Grounds remain partial. Neither admits a universal law, a physical source truth claim or an execution permission.

## Real E-CPU recovery, not a second consensus design

After independently reconstructing both VGI ledgers and their partial Grounds, the adapter stores the canonical evidence bundle using the existing AtomicGroundEvidenceStore (fsync, immutable SHA-256 content addressing). It seals the exact bytes using the native RecoveryStateManifest, RecoveryLineageAuthority, RecoveryLineageCoordinator and RecoveryLineageProof.

A fresh OS process reopens durable participant journals, verifies the latest majority-sealed root and exact bytes, reruns GCI-005 signature verification and reconstructs VGI's statuses from the retained original receipts. **It does not contact the original receiver processes again.**

Tests cover minority-prepared-but-uncommitted roots, stale generation rollback, signature tampering, trust-root changes, forged VGI status, altered evidence bytes and recovery with the original majority proof.

The three majority members are separate fsynced files on one research machine. This is not a physically independent, Byzantine or multi-administrator quorum.

## Hosted workflow integration

Rather than fabricate new E-CPU TLS readings, the existing CAG-004 / GCI-001–005 workflow gains a downstream iwi006_signed_vgi_quorum_recovery job after the successful GCI-005 **phase-blind auditor**. It uses the original process-generated signed agreements and disagreements from GitHub Actions artifacts.

The new job intentionally does **not** download or read the GCI-003 receiver-private phase. It rechecks the previous blind auditor's exact result. On main, it verifies existing GitHub workflow attestations for source, public Ground/plan, E-CPU network report and GCI-005 reports. This extra attestation gate is unavailable on unmerged pull-request runs.

## Limits and next research frontier

A signed feature reading is not proof of stationary machine-transition laws. A VGI finalization is policy-relative. A majority-sealed E-CPU artifact preserves accepted evidence identity but not the truth of a sensor, future stationarity, or events never observed. The VGI frame receipt is an **import** receipt, not the original raw TLS frame.

An end-to-end real E-CPU receiver **raw-frame ingress** into VGI remains a further integration opportunity. Stronger source-side invariant or controlled conformance evidence is still required to generalize observed events across time.
