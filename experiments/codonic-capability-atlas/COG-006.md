# COG-006 - Evidence-compiled cognitive capability Grounds

**Objective.** Construct a small, extensible structure of *competence*, rather
than generating a large implementation. An intention is resolved by a learned,
typed chain of reusable mathematical/relational operators. The selected chain
has sourced inputs, an explicit provenance obligation, and retained conversational
state. The chain is portable to a fresh interpreter after ledger reconstruction.

**Research status.** Synthetic, exact finite-model experiment. Not a general
chatbot, learned language model, natural-language parser, or autonomous intelligence.

## Why PyBot matters

`huggingface/pybot` describes a large rule-based conversational system built by
many agents without neural weights. The actual `bot/runtime.py` has observe,
respond, choose, and after phases; modules propose responses from isolated
memory snapshots and the selected candidate's memory is committed. Its
`bot/knowledge/__init__.py` organizes knowledge by domain and semantic keys.

**This work does not reimplement PyBot.** It explores whether a bounded subset
of the *structural role* of those components can instead arise from typed
relation-composition, evidence-directed program selection, and preserved memory.
Its example with the 30-minute kettle descaling procedure is referenced as a
single documented behavior, not a benchmark comparison to a live PyBot binary.

## Structure learned as DATA, not as Python source

A source Ground contains finite typed records with `subject`, ordered `steps`,
`direct_minutes`, and source provenance. An interpreter *grammar* contains
operators with declared interfaces:

    entity --direct--> minutes
    entity --steps--> step_list --sum--> minutes
    entity --steps--> step_list --first--> step --first_minutes--> minutes
    minutes --seconds--> seconds

The generic planner compiles all type-compatible chains to the requested output
type; it does not hardcode a procedure-specific decision tree. Initially three
plausible `entity -> minutes` programs exist. A finite observation version space
retains all paths consistent with witnessed task labels. Query selection favors
sources on which the candidates disagree. No program is promoted unless only
one remains. The witness chain commits to the source Ground and each example.

After two observations in the synthetic fixture, the promoted Ground is the
ordered composition `steps -> sum`. It then returns correct values for unseen
procedure records (that were never supplied as *training labels*) and can
compose with `seconds` to answer a new typed output demand.

This is **selection among an admitted primitive grammar**. It does not invent
arbitrary new operations, model natural language, or establish external truth.

## Memory as a computational requirement

A typed `mention(entity)` action sets the current referent. Subsequent
`ask_minutes` and `ask_seconds` intentions retain the referent and navigate only
the selected source record. Without a referent the system returns `unresolved`,
not an invented answer. `clear` deletes the reference. Every state mutation and
result is included in a predecessor-linked event record; `restore` recomputes
*both* the learned program and turn results and requires externally supplied
current head pins.

This is a small analog of a genuine follow-up relationship, not a claim that
textual pronoun resolution has been learned. The tests are intentionally typed:
the natural-language-to-intention compiler remains future work.

The native repository's `refine_to_transition_congruence` checks that memory
states with identical answers can be merged under a `duration-only` task, but
not under a task that also observes the exact subject identity. Equivalence
is **relative to the declared future observation contract**.

## Reproducible local findings (CPython 3.13)

| Source records | Ground preparation | Discovery | Observations | Correct unseen queries | Median prepared Ground query |
|---:|---:|---:|---:|---:|---:|
| 128 | 0.642 ms | 2.192 ms | 2 | 1,000/1,000 | 11.157 us |
| 4,096 | 70.270 ms | 1.791 ms | 2 | 1,000/1,000 | 11.227 us |
| 65,536 | 483.888 ms | 2.188 ms | 2 | 1,000/1,000 | 11.618 us |

Each query visits **one** fact, traverses **two** selected operator edges, and
performs a three-step integer sum. It does not perform a full search or
arbitrate against every expert. The times exclude storage reads, network,
GitHub Actions, natural-language interpretation, Hypervisor admission, and
external validation. Training pool has 128 candidate inputs; it is not a
65,536-way search. The source records are synthetic, with durations generated
by a deterministic formula, not acquired human knowledge.

Memory ablation: in 250 seeded referent-followup trials the retained context
answered the typed task exactly 250/250, while independent no-context queries
returned `unresolved` (0/250 answers). A separate Python process recreated the
Ground and continued the exact recorded session after validating external
head pins. The source and training digests are content commitments, **not**
authenticated observer signatures.

In an intentionally adversarial 100-subject acquisition pool, 90 subjects make
all competing programs agree and 10 distinguish them. One active query
identifies the correct relation program in 100/100 seeded trials; a random
query commonly leaves multiple candidates, making the benefit of attention
measurable without falsely calling the task open-ended intelligence.

**Local tests:** 14 tests; 13 pass and 1 native IFS transition-congruence test
skips because the parent repository is not mounted locally. The dedicated
GitHub Actions check must run that test without a skip when this file lives
inside In-Formation-Space; exact-head CI status is separate and unverified
until explicitly confirmed.

## Persisted evidence and cold execution

```sh
python -m unittest discover -s experiments/codonic-capability-atlas -p 'test_cognitive_grounds.py' -v
python experiments/codonic-capability-atlas/run_cognitive_grounds.py audit
python experiments/codonic-capability-atlas/run_cognitive_grounds.py prepare --path handoff.json
python experiments/codonic-capability-atlas/run_cognitive_grounds.py resume --path handoff.json --pins handoff.json.pins.json
```

`prepare` writes a portable checkpoint and a separate expected-head file;
`resume` reconstructs the catalogue, learning witnesses, and conversation
from a new process. The CI workflow executes these in distinct runner jobs,
transferring artifacts. All roles still share GitHub's repository/CI trust
context: this is **not** mTLS or fault-isolated quorum persistence.

## Rejected interpretations and critical next gates

* The word "intelligence" here denotes organization of useful processing,
  evidence-conditioned specialization, structured memory, and composition.
  There is no measured general intelligence, autonomous concept induction,
  or open-domain conversation.
* The PyBot README reports substantial agent-authored coverage and benchmark
  progress. We did not reproduce PyBot's benchmark or its full source behavior;
  our data is a toy analog of one relationship.
* Large catalogue sizes do not imply more information learned. They are
  separate from task performance and source-grounded facts.
* A finite source witness chain cannot prove all future utterances or establish
  authentication against an adversary who controls the supplied pin.

**Next proposed system gate:** adapt PyBot's actual understanding/knowledge
contracts into typed observation envelopes; learn new **feature operators**
from counterexamples; evaluate genuinely held-out multi-turn conversation
cases against a pinned PyBot baseline; and only then use E-CPU's real
Hypervisor + authenticated Transit + M3 quorum to realize and recover the
same selected capability across independent observer-hosts. Do not create a
parallel scheduler or signature authority.
