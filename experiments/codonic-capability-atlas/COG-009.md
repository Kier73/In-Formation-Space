# COG-009 — Signed observer ensembles driving partially known cognitive Grounds

**Status:** local actual-process result, native E-CPU and cross-runner CI pending verification. Stacked draft on COG-008. This experiment **does not generate code as cognition**: it takes COG-008's candidate cognitive *structure* and changes how its observations are acquired, qualified, challenged, retained and independently reconstructed.

## Existing components reused

- COG-006: typed `FactGround`, verified procedural `Learner`, `Session` behaviors.
- COG-007: the existing observation-table `ActiveMachineLearner`, learned `Machine`, and independent finite conformance auditor (for audit **after**, not during learning).
- COG-008: `ObservedOracle`, membership witness chain, `experimental_revision`, `checkpoint` and zero-source-call `recover`. No competing cognitive learner or alternative Ground language was created.
- E-CPU: `mailcpu.runtime_qualification.{QualificationPolicy,SubprocessQualificationEndpoint,qualify,verify_report}`. The hosted **native** gate installs an exact pinned E-CPU revision, tests the actual COG-009 observer process via E-CPU's SAB-003 on eight finite challenges, and includes post-restart retained-state verification. Native validation remains an independent pending gate until CI passes.
- IFS SRH-007/008 and RE-014–016: external trust anchors, Ed25519 signed independently verifiable evidence, explicit separation of authentication from truth, and no premature quorum/Hypervisor claim. This is a narrower application-specific research ensemble, **not** a reimplementation of those systems' actual mTLS, validator, quorum, or E-CPU authority.

## Architecture

Three physically separate **child processes** each execute the same pinned COG-006 synthetic source law. Every worker owns its operator-provisioned Ed25519 private signing key. The receiver independently enrolls its public key, exact source Ground epoch, typed action alphabet, and finite acquisition cost; no key included in a response is self-trusted. Before accepting membership results, each worker must pass a small signed behavioral qualification challenge (unknown when no referent, clear followed by unknown), which does **not** prove global source honesty.

One query carries a fresh unpredictable nonce, source epoch, typed action history, requested observer identity and canonical request digest. A worker signs the entire reply body using Ed25519 over SHA256(canonical body). The receiver refuses mismatched identity, nonce, path, epoch, public key fingerprint, signature, oversized frame and same-source equivocation. Every accepted signed observation is retained in a predecessor-linked immutable receipt ledger.

At least two **distinct enrolled** observer keys must report identical results before a membership observation is provisionally usable by the existing COG-008 learner. If the cheapest observers disagree, the receiver asks the next qualified observer, preserving the dissenting receipt. If the third source is unavailable and no two agree, the answer remains `unknown`; no fabricated tie-break or raw-majority truth claim. On restart, the same pinned key may resume in another process; an observer's new boot identifier is distinct. A committed query is not rerun just because an observer died.

The COG-008 `ObservedOracle` consumes this source directly; its `source_root` binds the entire enrolled roster and quorum policy. The learned predictive-state checkpoint is therefore not source-compatible with the old single synthetic Teacher merely because its actions happen to match.

The *independent* offline receiver sees only (a) the retained signed receipts, (b) externally presented hash pins and roster public keys, and (c) the COG-008 learned model/evidence. It rechecks every Ed25519 signature and complete receipt chain, reconstitutes qualified votes, checks each COG-008 membership label against a two-source signed agreement and reconstructs the old machine **without calling any observer or possessing any private key**.

### Exact distinctions in the evidence class

- **Signed source identity:** Ed25519 proves that the response originated from one of the enrolled private keys, under the declared content/nonce contract. It does not bind the key to a hardware identity.
- **Behavioral qualification:** finite bounded, receiver-specified probes establish demonstrated behavior only on those probes, with a fixed lease/policy in native SAB-003. This does not grant E-CPU Hypervisor execution permission.
- **Multi-source agreement:** two keys agreeing is evidence of reported consistency, **not source truth**. A negative test makes the two cheapest independently signed workers lie identically; their agreement is accepted as provisional but is false under the independent source reference.
- **Finite Ground equivalence:** after source acquisition, a separate finite-model reference can exhaustively check a synthetic hypothesis. This cannot certify an unknown open external environment or PyBot's full conversational semantics.
- **Process separation:** signed workers are separate OS processes, killed/replaced in the test. They share one machine, filesystem trust administrator, and synthetic source specification. There is **no** authenticated network TLS communication, fault-domain independence, host federation, consensus commit, authenticated M3 checkpoint, or GPU-free neural computation claim.

## Real direct test on the current machine

Commands from the experiment directory, with Python 3.11+ and `cryptography`:

```sh
python -m unittest -v test_multi_observer_fabric.py test_native_ecpu_qualification.py
python run_multi_observer_fabric.py prepare --subjects 32 --durations 8 --bundle demo32/bundle.json --trust demo32/trust.json --pins demo32/pins.json --private-dir demo32/private
python run_multi_observer_fabric.py resume --bundle demo32/bundle.json --trust demo32/trust.json --pins demo32/pins.json
```

The local 32-subject run acquired **4,529** unique source membership observations through signed worker exchanges, generated **9,193** signed source receipts, and rebuilt a **25-state** predictive machine; an *independent* complete finite-source check subsequently passed **3,589** reference-machine transition comparisons. A receiver in a separate new Python process independently verified all **9,193** Ed25519 receipts and every underlying COG-008 membership answer, then continued with zero host calls and no private keys. The 32-subject source Ground and vocabulary are synthetic; these counts do not measure real natural-language intelligence. Full signed bundle: approximately **11.5 MB**, while the learned quotient had 25 states: signing/evidence retention is not free.

The worker `alpha` is killed with `SIGKILL` after earlier commits. When the surviving `beta` (intentionally incorrect on the target) and `gamma` disagree, the fabric returns **unknown**. Restarting `alpha` with the operator's same enrolled key but a fresh process/boot resolves the dispute by independent agreement. Earlier committed observations are reused rather than executed anew.

**Negative controls:** (1) two independently signed but colluding sources can both be wrong; (2) rehashed signed-output forgery is rejected; (3) correct receipt replayed against a new nonce is rejected; (4) substituted external key enrollment and stale checkpoint pin are refused; (5) a host claiming a new result under unchanged source epoch is rejected; (6) missing independent agreement refuses output.

### Hosted native and fresh-job work

`.github/workflows/cog009-signed-observer-grounds.yml` includes Linux Python 3.11 and 3.13 live-process tests, a strict pinned-native E-CPU SAB-003 worker-qualification job and separate GitHub jobs for witness preparation and offline reconstruction. Its private keys are stored only under the producer job's temporary folder; the artifact contains the source ledger and enrolled **public** keys. The independently carried latest-head pins are passed as job outputs, not trusted from the artifact itself. This demonstration is one GitHub CI administration domain and must not be described as fully separated quorum custody.

2. Commit receipt + COG-008 model heads to E-CPU's existing M3/recovery-lineage quorum with monotonic generations, and test hard receiver death after prepared result but before ack.
