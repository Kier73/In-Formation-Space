# COG-008 — Partially observed, counterexample-revising cognitive Grounds

**Status:** experimental, source-linked; local finite synthetic observations verified. Native cross-job PyBot observations and GitHub Actions not proven until exact-head runs complete.

## Purpose

The previous COG-007 learner had an exact finite-model conformance oracle that could enumerate every declared source state and transition. It generated a correct minimal quotient, but such an oracle is not ordinarily available for a new observer-host, an external chatbot, or an expanding intelligence.

COG-008 deliberately **removes that authority from the learning path**. It reconstructs a predictive candidate from explicitly requested black-box membership observations and then challenges it with future continuations. A failed prediction becomes a source observation and a counterexample; the cognitive structure is revised in place. A candidate is always marked `provisional_finitely_challenged`, with *unexplored continuations = unknown*. COG-007's complete finite-model checker remains available only as an **independent audit** for synthetic fixtures where a complete reference exists.

This is about generative structure: learning and revising the relation between histories, future observations, and retained predictive state. It does **not generate Python modules** or use source-code volume as a proxy for intelligence.

## Evidence protocol and revision

The only permitted learning interface is:

`query([typed action ...]) -> [typed observed response ...]`

`ObservedOracle` binds a source epoch/root, action alphabet, bounded query count, and a hash-chained, indexed list of every unique requested membership observation. It accepts no independent source-state introspection. `recheck` compares an actually re-executed request to the recorded reply and refuses drift under an unchanged epoch. New source versions require new epochs.

COG-007's existing observation table produces a **proposed** predictive Mealy-machine Ground. `challenge_plan` tests state representatives under additional task continuations; for a named-subject contract, it explicitly challenges *each advertised subject* with `who`. The challenge source is only the external query endpoint. The first observed mismatch is retained as a counterexample; its suffixes extend the observation table, and the candidate is reconstructed. There is no assumed equivalence oracle and no assertion that a bounded challenge suite covers an infinite external environment.

The checkpoint commits the exact observed ledger and the actual COG-007 table representation, the tentative machine, the exact pins, counterexamples, resource counts, and epistemic status. A new Python receiver reconstructs the machine **using only the checkpoint's observed queries**; it independently matches the machine to the entire retained observation set and refuses stale/altered pins, new queries without evidence, source epoch changes, and forged machine content. Source-free reconstruction does not replay prior external work. A previously compressed state index cannot be silently mapped into a more refined structure after new evidence splits it; a symbolic access history is required for correct reinterpretation.

## Reproducible local synthetic audit

Run from the repo root:

```sh
python -m unittest discover -s experiments/codonic-capability-atlas -p 'test_partial_observation.py' -v
python experiments/codonic-capability-atlas/run_partial_observation.py audit
```

The reproducible six-case audit checks **3,000/3,000** held-out symbolic continuations; the separate 512-subject measurement independently checked **794,629** product-state/action edges and recovered the correct 25-state quotient. The representative trace `mention topic_0000 → minutes → repeat` falsifies the initial guess; under `who`, equal-duration but different named subjects furnish additional counterexamples.

**Critical negative control:** artificially restrict the challenger to 15 paths. Its candidate can pass all sampled probes and still FAIL independent complete conformance. Thus the system must retain `unknown`; a finite-test pass cannot become a universal truth claim by restating it.

These are **synthetic** operator relationships, not language understanding. The observation-derivation cost rises roughly with source alphabet/number of subjects, whereas the final task-relative memory quotient can remain small. The 512-subject case acquired 64,529 unique membership answers—an explicit cost, not O(1) discovery.

## Source-pinned PyBot test (hosted workflow only)

`pybot_membership.py` checks out the actual fixed PyBot Git commit, runs its real rule-based interpreter from a clean seeded conversation for each of eight finite multi-turn histories, and retains exact module names and reply strings. A separate GitHub job reconstructs the original observed ledger and independently reproduces the exact results from a fresh PyBot process. This demonstrates actual observed behavior only if hosted CI passes; it **does not claim the synthetic state machine implements PyBot's natural-language semantics or that PyBot is globally deterministic**.

The GitHub job output and artifact remain in a single CI trust domain. They cannot substitute for E-CPU's receiver-authenticated mTLS, signed validator identities, verified source provenance and quorum-recovery high-water commitments.
